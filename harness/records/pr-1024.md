## 手戻り

- 最初の計画は、セッションが書いた HTML を検査して全体を置く方式だった。実装の検証(指摘 13)で、マーカーの間の断片だけを書き builder が差し込む形に変えた
- ユーザーの判断で、1 ページを入口 + 3 ページに分けた(指摘 138)
- 技術のページの索引は、場所の表 → 行番号付きの抜粋 → merge-base からの diff と 2 つの表示、と 2 回作り直した。依存の図も 1 回描き直した
- ユーザーのデザインで、4 ページ・HTML 断片・`build-pr-explain-page.py`・`build-pr-explain-excerpt.py` を全面的に置き換えた。新しい形は 3 画面・`explain.json`・`build-pr-explain.py`・`check-pr-explain-template.py`・地図 v2・核の判定表。最初の回に人が退けた JSON に、人の判断で戻った
- 作り替えの前に main とコンフリクトし、マージで解消した
- 作り替えの実装で計画から外れた点(C1〜C6)は Issue に逸脱として書いた。ヘッダを 1 行にした判断は、後でユーザーの判断で戻した(指摘 151)
- 前半の回では、検証エージェントの実行中にコミット・push と作業ツリーの編集を挟んだ。harness-reviewer の 1 回は未コミットの変更を読んでいた。後半の回ではエージェントの実行中に git 操作をしていない
- 2 段目の security-reviewer と duplication-reviewer は、作業ディレクトリを git リポジトリと認識できず、ファイルを直接読んで判断した
- `run_in_background: false` で起動した検証エージェントも、背景で走った
- 公開した `explain.json` に、コミットごとの説明と差分への注釈が足りなかった。マージの直前に 2 回再公開して補った(指摘 152・153。リポジトリは無変更)
- マージ前に、main 側のデプロイで `pr-explain/` が 2 回消えた。再公開の途中で Actions の `put-map` と push が競合し、再試行で通った
- `echo hook-canary` は 2 回とも deny されずに通った。検証エージェントのマーカーも発火ログも無く、本当の不発だった(`hook-environment`)。フックが止めた操作は pre-push の 1 回だけ(指摘 154)
