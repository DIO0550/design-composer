## ゴールと結果

ゴールは「複数の `.dcmp` をタブで同時に開き、押して行き来でき、閉じられる。行き来しても各タブの
編集状態（選択・undo 履歴・ズーム）と自動保存・外部変更の監視が生きたまま保たれる」。達成した。

Issue 本文の見積もり（「自動保存・file watch・undo バッファ・エラー一覧がいずれも開いている 1 つを
前提にしている」）は**実物と違っていた**。すべて `OpenedDocumentEditor` のインスタンスに閉じており、
1 つ前提だったのは `DocumentSession` の型と `EditorScreen` の 2 箇所だけ。Rust 側は
`DocumentWatchers` がパス単位の `HashMap` なので変更 0 件。着手時に実物を読んで訂正し、Issue に
残した。

ゴールとのずれ: 無し。⌘W / ⌘1..9・並べ替え・自動保存デバウンス中の取りこぼしは
スコープ外として #565 / #566 / #567 へ切り出した。

## うまくいったこと

- **「見ていないタブも描いたまま残す」という差分の中心の判断を、ミューテーションで実測して
  テストに紐づけた。** 背面のタブを描かない形へ壊すと 5 件（選択が残る / ショートカット隔離 /
  監視が続く / 背面の外部変更 / 背面の自動保存）が落ちる。`hidden={!isActive}` を外すと 7 件。
  「この判断はテストが守っている」を言葉ではなく数で示せた。
- **実ブラウザ（Storybook + playwright）で `hidden` 属性が効いていることを確かめた。** DOM に
  `header` が 2 つあって見えているのは 1 つ、という形は happy-dom では確かめきれない
  （Tailwind を解決しないため）。
- **共通コンポーネントの切り出しが 0 ピクセルであることを実測した。** 切り出しの前後で
  `EditorScreen` の同じストーリーを撮り、`cmp` でバイト単位の同一を確認した。
- **plan-reviewer の 17 件のうち 2 件は、計画のままでは動かないもの**（ショートカットの全タブ発火 /
  複数ドロップの取りこぼし）だった。実装前に出たので、どちらも設計の追加で済んだ。
