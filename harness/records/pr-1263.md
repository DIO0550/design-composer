## ゴールと結果

ゴールは、コンテキストメニューの各行に併記する割り当てを、キーボードで実際に効く割り当て（`use-*-shortcut` の `KeyShortcut` 定数）から導くこと。片方だけ変えて食い違う状態を書けなくする。これは達成した。

- 10 個のフックの定数を公開し、メニューの表はそれを指すようにした
- 綴れない割り当ては、表に置いた時点で型エラーになる。対象は物理キー・空のキー・Shift だけの 3 形で、型テストで固定した
- 表示される綴りは変わらない
- GitHub 上の人のレビューは 0 件。`get_reviews` / `get_review_comments` / `get_comments` の 3 つとも確認した
  - `get_reviews` には Copilot の review が 1 件あり、指摘は 0（Approval recommended）
  - コメントは、自分が投稿したテストケース表と bot の投稿（Storybook プレビュー・CI レポート・VRT）だけだった
- CI は全件緑。VRT の差分は 0 件（206 件 passed）
- 並行していた #1253 と同じ型（`MenuShortcut` / `shortcutLabel`）に触れる。衝突を避けるため、型の形は変えずに入力の型で絞った

## 指摘

### 1. 空の keys で欄が黙って消える経路が残る

- 分類: `type`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: 変換が `ArrayEx.first` で `Option` を返すと、`keys: []` のときに割り当ての欄が黙って消える。入力の型の `keys` を `NonEmptyArray` に絞ったので、変換は `Option` を返さずに済むようになった。
- 既存ルール: rules/coding.md「不正な状態を型で表現できなくする」

- 既存ルール: rules/testing.md「assert は「落ちうるか」と「1つの仕様か」で見る」
