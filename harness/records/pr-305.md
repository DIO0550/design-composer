## ゴールと結果

ゴールは「右ペインの殻（幅・枠線・白地）の綴りが 1 箇所になり、`EditorLayout` のグリッドの 3 列目を直したらストーリー側が黙って古くならない（テストが落ちる）」。達成した。写しを `src/components/__stories__/right-pane-shell.tsx` の 1 部品に寄せ、`grep -rn "w-72" src` が 0 件になること・枠の幅とグリッドの 3 列目の一致をテストで固定することを確認した。

**Issue 本文は殻を「4 箇所」と書いていたが、実測では 7 箇所だった**（#301 で `components/` 側に増えた 2 本と、起票時から漏れていた `token-used-by`）。計画の前に grep で数え直したので実装前に拾えている。左ペイン側の同じ形 6 箇所（幅が `w-62` / `w-64` に割れている）は #304 として分離した。

human レビューは 0 件。CI は 1 回の push で全チェック success（視覚差分は `components/PaneBody / 中身が枠に収まらない` の 1 本が Changed で、枠の高さ `h-64` → 32rem による意図した差分。`visual-approved` で通した）。**指摘はすべてサブエージェント（`plan-reviewer` 11 件 / `implementation-reviewer` 10 分類）から出た。**

**この回の中心は 2 つ。** 1 つは、**ゴールを守るはずのテストが、狙った経路を守っていなかった**こと（指摘 1・11）。計画は「枠の幅とグリッドの列幅を定数として export し、文字列どうしを比べる」形で、これは class を直書きへ戻されても緑のまま通る（`plan-reviewer` が実装前に発見）。実装後も高さの枝（`content` / `pane`）を入れ替えても 2372 件が 1 件も落ちなかった（`implementation-reviewer` が実測）。もう 1 つは、**確かめずに書いたコメントが事実と食い違っていた**こと（指摘 5〜7）。「`flex flex-col` を持たせると本文が潰れる」は Chromium の実測で偽、「`overflow-auto` は効かない」は誤り、`text-sm` を落とせるという自分の見立ても実画面の読み違いだった。

## 手戻り

**実装のやり直しは 3 つ。** いずれも push 前（`implementation-reviewer` の指摘対応）で、コミットには 1 つの形しか載っていない。

1. **`text-sm` を落として戻した**（指摘 3）。実画面の字の大きさを本文の器（`PaneBody`）が持つと読み違えて落としたが、Storybook の実測で `PanelFrame` を使う 7 本すべてが動いた（`InstanceBody` 1.39% ほか）。実際は選択があるときの中身が `text-sm` を持っており、本文の内側に着せ直して 7 本とも 1px も動かないことを確認した。この読み違いはレビューに出る前に自分の実測で見つけた
2. **枠の名前を `PaneShell` → `RightPaneShell` に改名した**（指摘 5）。ファイル名・定数名も含む
3. **テストを定数比較 → 描画して class を読む形に作り替えた**（指摘 1）。`plan-reviewer` の実装前の指摘によるもので、これにより `EditorLayout` 側の変更と新しい export がまるごと不要になった

計画からの逸脱: 指摘 1 の対応で `EditorLayout` に定数を作って export する計画を捨て、`EditorLayout` 無変更・新規 export 0 個に変わった。
