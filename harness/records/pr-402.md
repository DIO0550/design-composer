## ゴールと結果

`placement: absolute` の子に `constraintX` / `constraintY` を持たせ、親の幅・高さを変えても子が意図した側へ追従するようにする。

**ゴールは達成したが、達成の仕方が Issue のスコープと変わった。** Issue 本文は「コンパイルで `left` / `right` / `translate` / `stretch` を出し分ける」だったが、キャンバスは親のサイズが変わるたびにドキュメント全体をコンパイルし直すため、どんな CSS を出しても同じ `x` から作り直されて既定 `min` と区別が付かない。**編集時に子の座標・長さを書き換える形**（Figma の実挙動）へ振り替えたうえで、着手前に Issue と Discord で確認して回答を得てから実装した。

## 手戻り

- **設計の差し替え（フェーズ 4 → 3 戻り）**: `AbsolutePlacement` に `constraintX` / `constraintY` を載せる計画を、`plan-reviewer` の指摘 3 / 7 / 13 を受けて取り下げた。constraint は編集時にしか効かないのに `Placement.fromProps` の可否ゲートに混ぜると、綴りが 1 つ不正なだけで座標ごと描画を失うため。結果としてテスト 34 箇所の書き換えも消えた
- **フックの適用点**: `resize` と `applyPropEdit` の両方に追従を挟む計画だったが、`resize` はノード相手のとき `applyPropEdit` を通るので**子が 2 度動く**（`plan-reviewer` の指摘）。実装前に 1 箇所へ寄せた
- **ミューテーションの混入と打ち消し**: 指摘 1 のとおり（`c4360bdd0` → `f0c06ae37`）
- **長さの変化判定の作り直し**: 指摘 4 の修正で `AxisLength.toPropEditIfChanged` を足したが、`create` が丸めたあとの値どうしを比べる形になり、`40.5` の子で「丸めてから同じか」を見てしまうことがテストで判明。既にある `AxisResize.create` を通す形へ作り直して、足したメソッドは消した
- **版の畳み込み**: 指摘 16 のとおり、1.3 へ上げたものを 1.1 へ戻した
