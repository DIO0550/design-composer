# PR #356 ファイル I/O の失敗の語彙を開く経路にも広げ、型名を実体へ揃える

- マージ日: 2026-08-29
- 関連 Issue: #354
- 差分規模: 22 ファイル / +243 -182

## ゴールと結果

開く経路（`features/document-start`）が `libs/document-ipc` の `DocumentIpcError` を直接
持っていたのをやめ、境界の詰め替えを通したドメインの語彙（`DocumentAccessFailure`）に寄せる。
あわせて、同期経路にしか合っていなかった型名 `DocumentSyncFailure` を両経路を覆う名前へ改名する。

**達成した。** `grep -rn "DocumentIpcError" src/features/document-start/` が 6 件 → 0 件。
`src/domains/` の production から `@/libs/` への import は 0 件のまま。ずれは無し。

なお Issue が挙げていた「判断が要ること」3 点は、着手時点では**ゴールが決まっていなかった**。
選択肢と根拠を Issue へ書いて停止し、回答（案 A-2 / 1 PR）を得てから計画へ進んだ。

## 手戻り

**改名と詰め替えを 2 コミットに分ける計画を、1 コミットへ変更した。**

分割を実際に組んでみたところ、改名だけのコミットでは `libs/document-ipc` の doc
（「開く経路と同期の 3 経路がこの 1 箇所を通る」）とドメイン型の doc（「開く・自動保存・
監視・書き戻しの 4 経路で 1 つの型を共有する」）が**まだ成立せず、doc が嘘になる**ことが
分かった。コミットの独立性（コミット単体で意味をなす）に反するため 1 コミットにまとめ、
分割しなかった理由をコミット本文の「代替案」に残した。

**実装後の手戻りは 0 件。** `plan-reviewer` の 9 件をすべて実装前に潰したため、
`implementation-reviewer` の指摘 7 件はいずれも doc の主張のずれで、コードの構造・
テストの作り直しは発生していない。

- **ゴールが決まっていない Issue で、推測で埋めずに停止した。** Issue が「判断が要ること」
  として 3 点を挙げていたので、選択肢・根拠・推奨を書いて回答を待った。停止の前に
  コードを読んで**判断に効く事実**を 3 つ取っている（`DocumentSyncFailureReason` を

  Rust の語彙と紛らわしい）ため、回答が 1 往復で済んだ
- **検査を `&&` で連ねず 1 つずつ走らせた。** oxlint が 0 件でも `biome check` は
  改名由来の整形差分 8 件で落ちた。連ねていたら末尾しか見えず、format 差分のまま
  push して CI を落としていた
