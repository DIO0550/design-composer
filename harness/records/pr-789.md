## ゴールと結果

ゴールは達成した。「PR が閉じる Issue のチェック」は、PR を作った直後(`opened`)に閉じる Issue が空で返ったとき、次の形で問い合わせ直す。

- 記録 PR でなければ、5 秒・10 秒の間を空けて 2 回まで問い合わせ直す
- 問い合わせ直しの途中で 5xx が 3 回続いたら、問い合わせ失敗として赤にする
- `PR_ACTION` が渡らなければ落ちる

この PR は #786(harness 棚卸し)の実装として出した。ところが #786 は、起動より前に棚卸しセッション自身の #787 でマージされていた。オーナー判断で #794 に付け替え、main を取り込んで #787 の実装をこの形に置き換えた。`対策済` は main の `at pr-787` のままにしている。

この PR 自身の `opened` のワークフローは走っていない(作成時に main と衝突していたため)。問い合わせ直しが実環境で働くかは、まだ見ていない。

人のレビュー指摘は 0 件だった(`get_reviews` / `get_review_comments` / `get_comments` の 3 つとも確認した)。コメントは bot の投稿と自分の報告だけ。CI は置き換え後の head で初回から緑。
