# PR #497 ✨ GUI からノード / artboard の名前を変えられるようにする

- マージ日: 2026-09-12
- 関連 Issue: #421
- 差分規模: 44 ファイル / +1584 -41

## ゴールと結果

`Layers` の行（ツリーと `Artboards` の一覧）のダブルクリック・コンテキストメニューの
`Rename`・`⌘R` の 3 つの入口から、artboard と その配下のノードの名前を打ち替えられる。
単一名前空間の一意性は保たれ、参照は壊れない。達成した。

Issue は「決めること 3 つ（参照の追随 / 衝突の扱い / 導線）が決まるまで実装単位に割れない」
判断の置き場として立っていた。着手時に選択肢と根拠を Issue へ書いて回答を待ち、
「全部 Figma をベースに、Figma に無いものはおすすめで」の回答を得てから計画へ進んだ。

**調査で Issue の前提が 1 つ崩れた。** Issue 本文は `name` の宛先を `ref` / `overrides` /
`binding` の 3 つとしていたが、`overrides` のキーは publicProps 名で単一名前空間の外
（`Component.applyOverrides` が `resolveOverrides(component.publicProps, overrides)` を通す）。
さらに GUI から選べるのは artboard と その配下のノードだけなので（`selectableName`）、
残る 2 つの宛先もこの操作では指せない。**結果として参照の追随コードは 1 行も書いていない。**

部品定義（`components` のキー）の改名は導線が無いためスコープ外にした。Issue を分けなかった
のは、このセッションの push 先ブランチが 1 本に固定されており、割っても PR は 1 本にしか
ならないため（理由は Issue に記載）。
