## ゴールと結果

Issue #44「部品化・解除 UI を実装する」に紐づいて起動したが、調べるとタスク 1〜4 と
完了条件 A / B は既に main に入っていた(#131 / #155 / #203 / #280 などの回に付随して
入り、#44 側に記録が残っていなかった)。配線も端から端まで到達を確認した。

未達は完了条件C(playwright-cli での操作確認)だけだったので、ゴールを次の 3 つに置き直した。

1. 部品化の入口が、凍結中も含めて押せる見た目と実際が一致している
2. 入力欄が開いた状態が視覚差分の対象になっている
3. 完了条件C の操作確認を行い、結果を記録する

**1 は取り下げた**(記録済みの設計判断と衝突していたため。指摘 1)。2 と 3 は達成。
production コードは変更せず、差分は story 2 本のみになった。

## うまくいったこと

- **完了条件C を playwright + Storybook で実際に操作して確かめた。** 単体 story の
  状態(入力欄の値・ボタンの `disabled`)だけでなく、`OpenedDocumentEditor` で
  部品化 → 部品一覧に追加 → 元位置がインスタンス → 解除 → 実ツリーに戻る、まで
  通しでクリックして絵を確認した。ツリーの行の綴りが
  `T home-title "ホーム"` → `◆ home-title inst` → `T home-title "ホーム"` と
  戻ることまで見えたので、完了条件 A / B を実物で言い切れた
- **実装が既に入っていることを、配線を辿って確かめてから結論した。** Issue の
  チェックボックスが未チェックであることを根拠にせず、`onCreate` から
  `DesignDocument.createComponent` まで、`actions.detach` から `DesignDocument.detach`
  までの経路を 1 段ずつ確認した
- **検証サブエージェントの指摘を握りつぶさなかった。** plan-reviewer の指摘で計画の
  中心を取り下げ、implementation-reviewer の指摘で自分が書いた doc の主張を撤回した。
  どちらも「直さない」で済ませられた場面だった
