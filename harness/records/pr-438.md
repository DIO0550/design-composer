# PR #438 Box に配置モード layout を入れ direction を吸収する

- マージ日: 2026-09-06
- 関連 Issue: #380
- 差分規模: 67 ファイル / +939 -264（3 コミット）

## ゴールと結果

`.dcmp` の Box に `layout: "free" | "row" | "column"`（既定 `column`）を入れ、`free` の Box を
flex コンテナではなく絶対配置の器としてコンパイルする。既存の `direction` は `layout` に吸収して消す。

**達成した。** ただし「`free` にすると何ができるようになるか」は、マージ後に人へ説明する段になって
初めて薄いことが分かった（指摘 2・3）。`free` が実際に変えるのは「flow の子が並ばなくなる」
「`gap` / `align` / `justify` が効かない」「子に `fill` を書けなくする」の 3 つで、**座標配置そのものは
`free` でなくてもできる**（`placement: absolute` は `layout` に関係なく効く）。Issue のゴール文は
この区別を持っていなかった。

人のレビューは版の引き上げについて 1 件で、丸ごと巻き戻して解消した（指摘 1）。

### 2. 「座標での配置は #381 の担当」が事実と違った

- 分類: `plan-scope-premise-verification`
- 出どころ: `レビュー（人）`
- 内容: 「free にしても自由に配置できないのは仕方ない感じ？」。計画も PR 本文も
  「座標での配置は #381 の担当」としていたが、**ドラッグでの座標の置き直しは #388 で既に
  main に入っている**（`use-node-drag` の `repositionCarrying` → `DropEdit.reposition` →

  artboard の中では `shift` が `none` になり、落とせず元に戻る。
  座標の経路は向きを使わない（`parentShiftAt` と `ChildPlacement.create` は名前だけ）ので、
  受け入れ先の解決を「名前まで」と「向きまで」の 2 段に分ければ塞がる
- 既存ルール: `plan-review.md`「既存のコードが前提にしている不変条件を、この計画が崩さないか」
