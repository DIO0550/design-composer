# PR #892 NumberEx.round の半端値が寄る向きを doc とテストで固定する

- マージ日: 2026-09-28
- 関連 Issue: #863
- 差分規模: 2 ファイル / +12 -3

## ゴールと結果

ゴールは達成した。`NumberEx.round` の半端値が +∞ 側へ寄ること（負の値のちょうど半分は 0 に近い側へ丸まる）が doc から読め、`round(-1.75, { fractionDigits: 1 }) === -1.7` のテストで寄る向きを固定した。丸め方そのものは変えていない。
CI は 1 回の push で緑、VRT は差分なし（181 件）。人のレビューは `get_reviews` / `get_review_comments` / `get_comments` の 3 つとも確認し、指摘は 0 件だった（`get_comments` は自分のテストケース表と bot の投稿のみ）。

## 指摘

### 1. doc に「四捨五入」を残すと「負の値は 0 に近い側」と一文の中で逆の読みになる

- 分類: `naming`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: 日本語の四捨五入は負の半端を 0 から遠い側へ寄せる丸めとして読まれる。同じ `Math.round` 由来の丸めを書いている `axis-length` の「四捨五入して(`.5` は大きい側へ)」に概要を揃えた。
- 既存ルール: rules/naming.md「名前と実体を一致させる」

### 2. 「ちょうど半分」が十進か二進かが doc から読めない

- 分類: `comment`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: `round(1.005, {fractionDigits: 2})` は `1`（`1.005 * 100` が 100.49999…）。「半分かどうかは二進の値で決まる」を `@returns` に 1 文足した。
- 既存ルール: rules/coding.md「コメントは doc と Why / Why not に絞る」

### 3. `Math.round(-0.5)` が `-0` を返す件が「未決の判断: 無し」から漏れていた

- 分類: `plan`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: 呼び出し側 2 件はどちらも非負で到達しないため doc には書かず、書かない理由を Issue に残した。
- 既存ルール: `.claude/skills/implementation-flow/SKILL.md` フェーズ 3「未決の判断」

### 4. 概要の「`.5` は大きい側へ」と `@returns` の「+∞ 側へ寄る」が同じ事実の二重記述

- 分類: `comment`
- 出どころ: `レビュー（implementation-reviewer）`
- 内容: `@returns` 側を「負の値のちょうど半分は 0 に近い側へ丸まる」だけにした。
- 既存ルール: rules/coding.md「コメントは doc と Why / Why not に絞る」

### 5. テストの入力に -1.75 を選んだ理由がコードに無かった

- 分類: `comment`
- 出どころ: `レビュー（implementation-reviewer）`
- 内容: 入力を「分かりやすい値」に差し替えると誤差で答えが決まる形に黙って変わるため、1 行コメントを足した。reviewer が挙げた反例 `-1.15`（10 倍で -11.499… になるとの主張）は node で実測すると `-11.5` ちょうどで成り立たず、例を `1.005 * 100` に差し替えた。
- 既存ルール: rules/coding.md「コメントは doc と Why / Why not に絞る」

### 6. `@param digits` の言い回しと `10 ** fractionDigits` の `digits.` 抜け

- 分類: `comment`
- 出どころ: `レビュー（implementation-reviewer）`
- 内容: 「小数点以下に残す桁数（`fractionDigits`）」と `10 ** digits.fractionDigits` に揃えた。
- 既存ルール: rules/coding.md「コメントは doc と Why / Why not に絞る」
