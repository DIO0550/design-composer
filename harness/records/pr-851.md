## 指摘

### 1. 重複検査側に違反ありのケースが無く、一覧の直し忘れを表が守れない計画だった

- 分類: `test`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: 計画のケースは重複検査側が rename（exit 0）の 2 行だけで、修正前の実装でも緑になる形だった。
  非 ASCII の `__tests__` フォルダに重複ヘルパーを足すケース（exit 1）を加え、修正前に落ちることを再現した。
- 既存ルール: rules/testing.md「assert は「落ちうるか」と「1つの仕様か」で見る」

### 2. ゴールが挙げたタブのケースが無かった

- 分類: `test`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: rename 表をタブ区切りへ詰め替える実装に戻しても、非 ASCII と `"` のケースだけでは落ちない。rename 側の `"` のケースをタブに置き換えた。
- 既存ルール: rules/testing.md「assert は「落ちうるか」と「1つの仕様か」で見る」

### 3. 形式を変えると嘘になるコメントがファイル表に無かった

- 分類: `comment`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: `added-lines.sh` の「rename の対応表(新しいパス -> 古いパス)を作る」が、生の `-z` 出力を置く形では事実と違う。
  書き直し、`-z` で読む理由と `core.quotePath=false` を採らない理由を冒頭に残した。
- 既存ルール: `.claude/skills/implementation-flow/SKILL.md` フェーズ 3 手順 7

### 4. 「未決: なし」の裏に pathspec のグロブ解釈が隠れていた

- 分類: `plan`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: `git diff -- "$file"` はファイル名を pathspec のグロブとして解釈する。`[ab].ts` で `a.ts` のハンクも混ざることを実測した。
  クォートとは別の穴で、誤検出側なので #849 に分離した。
- 既存ルール: `.claude/skills/implementation-flow/SKILL.md` フェーズ 3「未決の判断」

- 既存ルール: `.claude/skills/implementation-flow/SKILL.md` フェーズ 3 手順 6

### 6. 却下理由「mawk は RS="\0" を扱えない」が事実と違った

  Issue で理由を取り下げ、コード側の Why not コメントも消した。タブ区切りへ戻す退行は判定表のタブのケースが守る。
- 既存ルール: `.claude/skills/implementation-flow/SKILL.md` フェーズ 3 手順 5

### 7. set -e の下で while の終了ステータスが 1 になる形で書いていた

- 内容: `rename_source_of` を `[ ... ] && { ...; return; }` で書いた。一致しないと while が 1 を返す。
  コマンド置換のサブシェルでは errexit が継承されないので偶然通っていた。`if ... fi` に直した。
- 既存ルール: rules/coding.md「外部の挙動は動かして確かめる」

### 8. 重複検査の一覧を quotePath=false 版にするミューテーションが生き残った

- 内容: 重複検査側で `"` やタブの違反ありケースが無く、この書き換えで表が全行 ok のままだった。
  rename の行は「丸ごと外れた」ときも exit 0 で通る。タブを含むフォルダの違反ありケースを足し、同じミューテーションで落ちることを確かめた。
- 既存ルール: rules/testing.md「assert は「落ちうるか」と「1つの仕様か」で見る」
