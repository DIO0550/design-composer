## ゴールと結果

ゴールは達成した。スキーマに無い type のノードを渡しても `ResolvedProps.forNode` は例外を投げず、`none` を返す。呼び出し元 3 箇所(`axisLengthOf` / `followPropEdits` / `childPlacementOf`)は `none` で分岐する。
着手前に、main で `childPlacementOf`・ノードへの `applyPropEdit`・artboard の `resize` が `TypeError` になることを一時テストで確かめた。
人のレビュー指摘は 0 件(`get_reviews` / `get_review_comments` / `get_comments` の 3 つとも確認。コメントは bot の投稿と自分のテストケース表だけ)。CI は初回で緑。

## 指摘

### 1. resize で長さだけ書かれて座標が書かれない非対称を計画が扱っていなかった

- 分類: `plan`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: `resize` は `nodePositionPropEdits` 経由で `childPlacementOf` を使うので、スキーマに無い type では座標が書かれなくなる。
  非対称を受け入れた。理由(UI では始点側のハンドルが掴めない)を Issue に書き、「座標が変わらない」テストを足した。
- 既存ルール: `.claude/skills/implementation-flow/SKILL.md` フェーズ 3 手順 7

### 2. 挙動が変わる doc がファイル表から抜けていた

- 出どころ: `レビュー（plan-reviewer）`
- 内容: 計画は呼び出し元 3 つの `@returns` しか挙げていなかった。`resize` / `nodePositionPropEdits` / `withResizeFollowUp` / `EditorState.repositionSelectedNodeBy` の列挙も変わるので、grep で仕分けて足した。
- 既存ルール: `.claude/skills/implementation-flow/SKILL.md` フェーズ 3 手順 7

### 3. constraint の「動かない」テストの入力が指定されていなかった

- 分類: `test`
- 出どころ: `レビュー（plan-reviewer）`
- 内容: スキーマに無い type の子に `max` と座標が無いと、生の props で追従させる誤った実装でも通る。入力に `constraintX: "max"` と座標を持たせた。
- 既存ルール: rules/testing.md「assert は「落ちうるか」と「1つの仕様か」で見る」

### 4. 確かめ済みの型を要求する案が却下案に無かった
