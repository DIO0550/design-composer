## ゴールと結果

ゴールは「右ペイン（プロパティパネル）が `features/inspector/` として独立し、`EditorState` を受け取らずに描ける」。達成した。#174 の feature 分割の 4 つ目（#250 tokens・#251 assets・#253 sidebar に続く）。

移したのは 1 モジュール（`property-panel`。実装 1,048 行 + テスト 6 ファイル + ストーリー）。`EditorState` の 3 箇所（`documentSelection` / `singleSelection` / `isFileInvalid`）を `DocumentSelection` 1 つと `isFrozen` に置き換え、器（`EditorLayout.RightPane`）を着せるのは呼び出し側に残して `PropertyPanel` を `Title` / `Body` に割った（`features/tokens` の `TokenEditor` と同じ形）。`inspector → editor` の import は 0 件。

human レビューは 0 件（reviews / review threads とも 0、コメントは bot の 3 件のみ）。CI は 3 ワークフローすべて 1 回目で success。**指摘はすべてサブエージェント（`plan-reviewer` 10 件 / `implementation-reviewer` 11 件）から出た。**

テストは 350 ファイル / 2363 テスト。

**この回の中心は、割ったことで保証の性質が変わったのに doc が古い主張のまま残ったこと（指摘 12）。** 割る前の `PropertyPanel` は `controls` を 1 回だけ計算して帯と本文へ配っており、食い違いは構造上作れなかった。`Title` / `Body` に割った後は別々の `selection` を渡せてしまい、保証は呼び出し側の規律へ移っている。コード上は正しく動くので、テストも typecheck も何も言わない。

**2 番目は、器を着せる 8 行が Tokens と inspector の 2 箇所に増えたこと（指摘 11）。** 切り出しの副作用として生まれた重複で、器を 1 箇所へ寄せ直したら帯の器を落としたときに落ちるテストが 1 件 → 10 件以上に増えた（実測）。
