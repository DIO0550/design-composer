## うまくいったこと

- **すり抜け（出どころ=レビュー（人））という機械的な指標で対象を選んだ。** 再発数だけで見ると
  `hook-environment` 等が上位に来るが、それらはすり抜け 0 件（サブエージェントのレビューでは
  捕まえられているが人まで届いていない）であり、`harness-growth` の SKILL.md の指針どおり
  すり抜けが最大の `ui-fidelity` を選んだ
- **2b の「前回と同じ層への追記は選択肢に入れない」を厳密に守った。** `rules/ui-verification.md`
  への追記も検討したが、pr-199 の rules 追記後も再発している実測データそのものが「読み手の
  記憶に頼る層は弱い」ことを示していたため見送り、観点層（`plan-reviewer` /
  `implementation-reviewer`）へ上げた
- **`対策済` 行の自己参照問題を、PR 作成後の実際の番号でフォローアップコミットして解決した。**
  pr-457・pr-467 の記録が同じ問題を「積み残し」として残しているのに対し、今回は
  PR 作成 → 番号確認 → 同じ PR への追記、という手順で積み残しを出さなかった
- **PR を `subscribe_pr_activity` で監視し、CI green・レビュー 0 件を確認したうえでマージされる
  まで見守った。** マージ後は自動で unsubscribe された
