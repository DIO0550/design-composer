## 規約への反映

置き場所は Step 4 に従い強制力の強い順（フック → 新しいスキル → 既存スキルの観点 → `rules/`）
に検討し、**採らなかった理由も残す**。

### `duplication`（12 回）→ フック（#1）

`.claude/hooks/check-test-helper-duplication.sh` と
`.claude/hooks/lib/duplicate-test-helpers.py` を足した。同じ `__tests__/` の中に
**本体が一字一句同じ**ヘルパーが 2 つ以上いれば知らせる。

**これは機械的に判定できる。** 「本体の文字列が完全に一致するか」は白黒が付き、判断が要らない。
`check-test-rules.sh` が「`test()` ブロックの中だけ」と対象を絞って成立しているのと同じ形で、
「同じ `__tests__/` フォルダ」「本体が完全一致」「20 文字以上」に絞っている。

`rules/` と `implementation-review.md`（PR #145）には既に基準が書いてあるのに 12 回出ている。
**足りないのは基準ではなく検出**なので、いちばん強い側へ上げた。

**ブロックにしなかった理由**: 導入時点でリポジトリに**既存の重複が 13 組**あった
（`--all` で機械的に数えた）。触っていない分まで push を止めると、直す気の無い違反を
避けるためのエスケープハッチが増え、フック全体が信用されなくなる
（`.claude/hooks/README.md`「例外(エスケープハッチ)」が記録している失敗の形）。
**編集したファイルが絡む重複だけ**を報告する形にし、既存 13 組の解消は #153 に分けた。
解消後にブロックへ格上げするかは改めて判断する。

### `test-behavior`（19 回）→ 既存スキルの観点（#3）

`implementation-review.md`「テストが守っているかの観点」の UI 向けの記述を、
**消してみる対象の一覧**に書き換えた（アイコン / 読み上げ名 / 器 / 状態からの配線 /
位置・大きさ）。「アイコン・ラベル・器のどれを消しても落ちない」とだけ書いていたのを、
実際に踏んだ 5 種類の表にした。

あわせて**位置・大きさは happy-dom では落とせない**ことを明記した。class 名を assert すると
実装詳細のテストになるので、テストで留めずに「気づく手段が Storybook の視覚差分だけである」
ことをコードのコメントへ書く、という扱いにする。

**フック（#1）にしなかった理由**: PR #150 で書いたとおり、全テストを変異ごとに回すと CI 時間が
跳ね、「差分の中心の判断」を選ぶところが機械化できない。今回もそこは変わらない。
**新しいスキル（#2）にしなかった理由**: 段取りが増えたのではなく、既にある観点の
**対象の一覧が粗かった**だけ。フェーズ 6 で必ず読まれる場所にあるので、そこを厚くすれば届く。

### `plan`（16 回）→ 既存スキルの観点（#3）

`plan-review.md`「変更で壊れる既存の資産を洗い出しているか」の隣に、
**「消すものがある計画なら、それを最後に使っていたものを数えたか」**を足した。
見るものを 3 つ（呼び出し元が 0 になる props / メソッド、消したものに言及しているコメント、
画面から消える操作の代わりの入口）と、それぞれの探し方を表にした。

指摘 2・3 はどちらも「消した結果」を数えていなかったことが原因で、**typecheck も lint も
落ちない**のが共通している。

**フック（#1）にしなかった理由**: 「呼び出し元が 0 になった export」は原理的には機械判定
できる（`knip` 等）が、それは**計画の検証ではなく実装後の検査**で、この分類が出る場所
（計画の段階）には届かない。導入するなら別の単位で、`plan` とは別の話として扱う。

### `ui-fidelity`（5 回）→ `rules/` の表現を直す（#5）

`rules/ui-verification.md` の「綴りの回数を数える」の直後に、
**`-i` を付けること**と、`text-transform:uppercase` で字面が変わる実例を足した。

**それより上を採らなかった理由**: フック（#1）にはできない（私が頭の中で grep をどう打つか
の話で、コードに現れない）。新しいスキル（#2）でもない（段取りではなく注意 1 つ）。
既存スキルの観点（#3）にも置けるが、**数え方は UI 案の読み方の一部**なので、読み方を
書いてある `rules/ui-verification.md` に隣り合わせで置くのが読まれやすい。
