# PR #139 左ペインをアイコンレール + Assets パネルにする

- マージ日: 2026-08-08
- 関連 Issue: #129
- 差分規模: 38 ファイル / +1584 -360

## ゴールと結果

左ペインを「56px のアイコンレール + 248px の見出し付きパネル」にし、`Assets` パネル
（部品のパレット）から Primitives と Components を見て部品インスタンスを挿せるようにする。
`Search assets` で両方を絞り込める。**達成した。**

ずれたのは 1 点。計画では「レールのアイコンは外部依存が禁止なので Unicode の字面で
近似する」を未決として残していたが、計画検証で「UI 案のアイコンは素の div で描かれて
いる」と指摘され、前提そのものが誤りだった（下の指摘 4）。

## 指摘

### 1. 編集画面レベルのテストの置き場所を誤ろうとしていた

- 出どころ: 自己修正（計画検証のサブエージェント）

  そこはヘルパー専用の置き場で、テストは `opened-document-editor/__tests__/` に
  `setup.tsx` を共有する形で 9 ファイルある。既存の形へ寄せた
- 既存ルール: rules/testing.md「配置と命名」
- 次にどう防ぐか: 今回は記録のみ（1 回目）

### 2. リネームで既存テストの観点が落ちかけた

  新テストは 5 ケースしか挙げていなかった。ファイルをリネームして 10 ケースを丸ごと

  （ただし**既存テストの観点を引き継ぐ**ことには触れていない）

### 4. レールのアイコンを「外部依存が禁止だから再現できない」と決めつけていた

  理由にならなかった。div で同じ形を組んだ
- 既存ルール: rules/ui-verification.md「UI を実装・変更する前に必ずこのファイルを開いて
  該当箇所を見る」— **開いてはいたが、スクリーンショットだけ見て DOM を見ていなかった**
- 次にどう防ぐか: 今回は記録のみ（1 回目）

### 5. 同じ絞り込みが 2 箇所に出る計画になっていた

  pr-122 の指摘 5（`なし`として記録）と同じ話で **2 回目**

### 6. 行き先の union に対する出し分けが暗黙の default になっていた

### 7. コメントの主張と実装が食い違い、到達しない分岐を通っていた

- 次にどう防ぐか: 今回は記録のみ（1 回目）

### 8. 絞り込み 0 件を「部品がありません」と言い換えていた

- 分類: `over-guard`

- 内容: 検索でどれにも一致しないとき、ドキュメントには部品があるのに `ComponentList` が

- 既存ルール: implementation-flow フェーズ 6「握りつぶした結果の隠蔽」
- 次にどう防ぐか: 今回は記録のみ（1 回目）

### 9. 型で守ろうとして可読性を落とした（対応表 vs `switch`）

- 分類: `illegal-state`
- 出どころ: レビュー（オーナー）
- 内容: 指摘 6 への対策として行き先ごとの対応表（`satisfies Record<LeftPaneView, ...>`）に
  したが、値が props 一式を受け取る関数になり、呼び出しが
  `CONTENTS[view]({ view, onSelectView, state, node, token })` と、どの行き先も使わない
  値まで渡す形になっていた。`switch` の戻り値を `ReactNode` ではなく `ReactElement` に
  すれば同じ網羅性が得られると分かり、`switch` へ戻した
- 既存ルール: rules/coding.md「不正な状態を型で表現できなくする」（ただし
  **網羅性をどう得るかの書き方が無い**ため、対応表という遠回りに行った）
- 次にどう防ぐか: 書き方を rules/coding.md に追記した（下の「改善」参照）

### 11. `Object.values` で走査したレールに、行き先でない値が並んだ

## 手戻り

- **指摘 6 → 9 の往復**が最大の手戻り。「暗黙の default を潰す」ために対応表へ寄せ、
  レビューで「読みにくい」と言われて `switch` + `ReactElement` に戻した。
  最初から「網羅性は戻り値を非 nullable にすれば `switch` で得られる」と知っていれば
  1 回で済んだ（改善 2 はこれを潰すためのもの）
- 型の名前を `ComponentUsage` → `ComponentAsset` に変えた。計画検証で
  「`publicPropNames` は使われ方ではないので `Usage` は約束しすぎ」と指摘されたため
- PR 本文に書いた「0 件でも見出しは残す」が実装と食い違っており、レビューで指摘された。
  実装が正しく説明が誤っていたので、説明を直して理由をコードとテストに残した

## うまくいったこと

- **UI 表示確認がテストで落ちない不具合を捕まえた**（指摘 11）。
  rules/ui-verification.md「コードを書いた・テストが通っただけでは完了とみなさない」が
  そのまま効いた形で、この 1 件だけでも表示確認の手順に価値があった
- **計画を Issue に書いてから検証に回す順序**が効いた。指摘 1〜5 はすべて実装前に出て
  おり、コードを書いてから直すより安く済んでいる
- 却下案を Issue に残していたため、レビューで「なぜ挿入ボタンを付けないのか」
  「なぜ節ごと消すのか」に即答できた
