# PR #384 絶対配置の子を入れ、キャンバスのドラッグで座標を動かす

- マージ日: 2026-08-31
- 関連 Issue: #379 / #381（#370 から分割）
- 差分規模: 84 ファイル / +2455 -263（16 コミット）

## ゴールと結果

#379: `.dcmp` のノードに `placement: "absolute"` と `x` / `y` を書けるようにする。
#381: キャンバスでそのノードを掴んで運んだときに、ツリーの並べ替えではなく座標の置き直しになる。

両方とも達成した。ただし**当初のゴールは 2 回広がっている**。

1. #379 だけの PR として出したあと、オーナー判断で #381 を同じ PR に載せた（分けても
   単独ではマージしても何も動かないため）
2. #381 を実装したあと、オーナーが実機で触って**運んでいる間の表示が無い**ことと
   **ノードを親の外へ運ぶと消える**ことを指摘し、ドラッグ中のプレビューと座標のクランプが
   後から入った（指摘 7・8）

最終的に、Figma のモデル（親が auto layout かどうかで意味が決まる）とは主語が違う状態のまま
出している。そこは #380 / #388 に切り出した。

## 手戻り

4 件。

1. **UI 案の読み違い（指摘 1）で実装を止めた。** 「A は新しい語彙を足さないので確認不要」と
   いう進行の根拠が消えたため、実装を中断して Issue を訂正し、オーナーへ選択肢を出し直した
2. **PR のスコープが 2 回広がった。** #379 単独 → #381 を同じ PR に載せる（オーナー判断）→
   ドラッグ中のプレビューを追加（オーナー指摘）→ クランプを追加（オーナー指摘）。
   そのたびに PR 本文とテストケース表を書き直しており、途中のコメントに貼った表は
   すべて古くなっている
3. **クランプの帰属先を計画中に 3 回変えた。** `Placement.clampWithin`（ドメイン）→
   artboard 基準 → 直近の親基準の feature domain。`Placement.moveBy` の doc が
   「負の座標が親からはみ出した位置として成立する」と明記しているのを読んで、値の語彙には
   持ち込まないと決めた
4. **測り方を `getBoundingClientRect` から `clientWidth` へ変えた。** 前者はドラッグ中の
   プレビューの `transform` が乗るので、掴んだ時点の大きさが取れないことに気づいた

  分かって初めてテストを足している
- **オーナーの「バグる」を憶測で直さず、実機で 3 つに切り分けた。** Storybook + playwright で
  座標を実測し、(1) 親の外で消える (2) ドラッグの意味を決める主語が Figma と違う
  (3) reparent されない、に分けて選択肢を出した。1 だけがこの PR の退行で、2 は #380、
  3 は #388 という切り分けができたので、この PR に載せる範囲が決まった

  `pointermove` ごとに積まれる問題は「expected 450 to be 360」を再現してから #387 に切り出した
- **ドラッグ中の表示は VRT で守れないことを自覚して、代わりの担保を置いた。** 静止画に
  出ないので視覚差分では捕まらず、新しいストーリーは `new` 扱いで差分にも数えられない。
  配線テスト（プレビューの規則を見る）と playwright の実測でしか守れないことを PR 本文に
  書いたうえで、両方を実行した

無し。`harness-record` の管轄は記録を 1 ファイル足すところまでで、集計・介入の判断・
`rules/` やフック・スキルの変更は `harness-growth` が行う。

この回の材料は次の 3 点。

- **すり抜けが 2 件**（指摘 6・7。どちらも `レビュー（人）`）。2 件とも**実機で触るまで
  誰も気づかなかった**もので、計画・実装の両方のサブエージェントを通過している。
