## ゴールと結果

ゴールは「トークン編集一式が `features/tokens/` として独立し、`EditorState` ではなく値（表示中のドキュメントと選ばれているトークンの対）を受け取って描ける」「`EditorState` から `isTokenSelected` / `tokenReferrers` / `tokenReferrerNodeNames` が消える」。達成した（`grep -rn "@/features/editor" src/features/tokens` = 0 件 / 3 メソッドは `src/` に残っていない）。

Issue 本文の見立てからは 4 つずれた。**`token-template` を移さない**（追加の受け口を `TokenTemplate` から `TokenKind` に変えたので、tokens 側が指定を知る必要そのものが消えた）、**`use-token-actions` を移さない**（`useEditor()` と `EditorAction` が `editor` の器で、移すと循環する）、**導出 3 メソッドを feature ではなく `src/domains/token-selection/` へ置く**（消費者が tokens の 3 コンポーネントと `editor` の `artboard-frame-list` にまたがる。`tokenReferrerNodeNames` の 2 番目の消費者は Issue 本文に無かった）、**`EditorState` は 41 → 38 ではなく 41 → 39**（対を渡す `tokenSelection` を 1 つ足した）。ずれはすべてマージ前に Issue へ書いた。

human レビューは 0 件（レビュー・レビューコメントとも 0。PR のコメント 3 件はすべて bot）。CI は 6 チェックすべて 1 回目で success（視覚差分は Changed 0 / New 14 / Deleted 14 = ストーリーの移動分のみで、`visual-approved` は不要だった）。**指摘はすべてサブエージェント（`plan-reviewer` 18 件 / `implementation-reviewer` 5 件）から出た。**

## 手戻り

- **1 つ目のコミットが、`git mv` で index に載っていた rename をすべて巻き込んだ。** ファイルの移動を先にまとめて済ませていたため、`git add <新設ファイル>` だけを指定しても、既に staged だった 22 件の rename が同じコミットに入った。`git reset --mixed HEAD~1` でやり直し、パスを明示して 3 コミットに分けた
- **中間コミットが「各コミットでビルドが通る」を満たさない形になりかけた。** `type-glyph` の昇格だけを 1 コミットにすると、旧パスに残る `token-used-by`（HEAD の内容）が消えた `type-glyph` を import する。`git show HEAD:<旧パス>` から import 行だけ直した版を一時的に作って staged し、次のコミットで削除する形にした
