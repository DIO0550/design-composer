# PR #261 [architecture] libs の境界を掃除する（外部フォーマットの解釈を libs へ戻す）

- マージ日: 2026-08-19
- 関連 Issue: #247
- 差分規模: 44 ファイル / +415 -413

## ゴールと結果

ゴールは「`src/domains/` から `@/libs` への辺を作らずに `document-error` / `document-reload` / `file-validity` を `src/domains/` へ置ける状態にし、テキストの解釈とその失敗を `DocumentError` へ揃える変換がどちらも `libs/document-json` に閉じている」。達成した（`grep -rn "@/libs" src/domains` = 0 件 / `grep -rn "@/features" src/domains` = 0 件）。

Issue が挙げていた 3 つの作業に加えて、**中間型 `DocumentJsonError` そのものを消す**判断を計画時に足した。この型は 3 系統（字句スキャン / 版の解決 / 形の検証）の失敗を `path?` / `position?` がどちらも省略可の 1 つの形へ潰し、feature 側の `locationOf` が「`position` があれば文字位置、`path` があればパス、どちらも無ければ全体」と推測で復元していた。変換が `libs` に戻ると由来ごとに直接 `DocumentErrorLocation` を組めるので、潰す → 復元する往復が要らなくなる。Issue の「注意」が言っていた「3 系統との対応が崩れていないか」も、この復元が消えることで確認する対象そのものが無くなった。

human レビューは 0 件（レビュー・レビューコメントとも 0）。CI は 6 チェックすべて 1 回目で success（視覚差分も差分 0 / passed 105）。**指摘はすべてサブエージェント（`plan-reviewer` 12 件 / `implementation-reviewer` 9 件）から出た。** うち計画側は 11 件、実装側は 8 件を受け入れた。
