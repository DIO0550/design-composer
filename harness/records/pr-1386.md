# PR #1386 usage() を .github/scripts/lib/usage.sh へ寄せ、lib を読み込めなければ 127 で止める

## ゴールと結果

ゴールは「`.github/scripts/` の重なり(`usage()` の本体、n 回まで・n × 待ちのやり直しの骨組み)について、寄せる部分は `.github/scripts/lib/` の 1 か所から読まれ、寄せない部分はその理由がコードか Issue から辿れる。振る舞いは変えない」。達成した。`usage()` は `lib/usage.sh` の 1 か所になり、2 本は `. … || exit 127` で読む。やり直しの骨組み(4 本)は寄せず、理由を #1341 の却下案 A〜F に残した。`check-*` 2 本の問い合わせを寄せる案は #1377 に申し送り、doc と実装のずれは #1385 に分けた。

lib を読む形にしたことで「lib を読み込めない」という新しい失敗の経路ができた。`set -uo pipefail`(`-e` なし)なので、guard が無いと pr-explain-pages は知らないモードでも gh-pages へ push して exit 0 になった(試作で実測)。これを 127 で止め、判定表で守ることがゴールに加わった(計画の検証で見つかった)。

GitHub 上のレビューは `get_reviews`・`get_review_comments`・`get_comments` の 3 つとも確認した。bot の指摘が 1 件(Devin Review)あった。人のコメントは、その指摘への判断(「このままでいい」)が 1 件だけで、指摘ではない。`get_comments` は自分が投稿したテストケース表と bot の投稿(Storybook プレビュー・CI レポート・VRT)だけだった。CI は全件緑で、VRT の差分は 0 件(209 件 passed)。

## 手戻り

- 計画を 2 回立てた(`plan-reviewer` の 4 件をすべて採用。指摘 1〜4)。2 回目の計画で lib 欠落の経路と 127 が加わり、ファイル表は 5 本のまま、テストは 1 行から 3 行に増えた
- 実装の検証で `implementer` を 2 回起動し直した。1 回目は comment-reviewer #3 と harness-reviewer #1(指摘 5・8)、2 回目は test-reviewer #1(指摘 9)
- `run_in_background: false` を指定した `implementer` / `test-reviewer` も背景で起動された。完了通知を受け取るまで git 操作はしていない
- 計画の未決(upsert の待ち時間の doc のずれ)は #1385 に分離した
- push 前の検査は 1 つずつ実行した。`PRE_PUSH_REQUIRE_ALL=1 bash harness/githooks/pre-push` は exit 0(失敗 0 / 通過 32 / 飛ばした 0)、`pnpm run typecheck` / `pnpm run lint` / `pnpm exec biome check` / `pnpm run test:run` はいずれも exit 0
- フック不発: push 前の `echo hook-canary` が通り、実行中フラグのマーカーも発火ログも無かった(`.claude/hooks/README.md` の表で本当に不発)。代替不能なフックの肩代わり確認(親の編集・`npx`・`git add -A`・検証エージェント実行中の git 操作)はいずれも該当なし
