# PR #244 [ui] padding を 1 行に束ね、個別 / 垂直・水平をボタンで切り替えられるようにする

- マージ日: 2026-08-18
- 関連 Issue: #230
- 差分規模: 34 ファイル / +1464 -218

## ゴールと結果

ゴールは「Box / artboard の Layout セクションで padding が 1 行にまとまり、既定では垂直 / 水平の 2 欄、切り替えボタンで T / R / B / L の 4 欄になる。畳んだ欄の編集は対応する 2 辺へ同じ値を書き、**undo 1 回で両辺が戻る**」。達成した。

Issue が挙げていた「決めること」3 つには次の形で答えた。

1. **束ね方の宣言** → スキーマの `PropDefinitionBase` に `shorthand?: { name; side }` を足した（4 辺という概念をスキーマが知る形。一般の「N 個を 1 行に束ねる」は畳んだ 2 欄の対応を表現できないので採らない）
2. **不揃いの見せ方** → `<select>` の未選択スロットの綴りを `不揃い` に差し替える
3. **解決値の併記** → 出す。ただし半幅セルでは欄の下段へ回す

ゴールからのずれで**記録すべきものが 1 つある**。Issue 本文には無かった論点として、`EditorState.applyPropEdit` が 1 回ごとに `EditHistory.record` を呼ぶため「畳んだ欄の編集を辺ごとに分けて適用すると undo が 2 段になる」ことが計画中に判明し、`PropEdit` の書き込み先を `name: string` から `names: readonly [string, ...string[]]` へ広げる変更が前提として増えた。Issue の分割判断としては「呼び出し側がこの Issue にしか無く、先に入れると呼び出しの無い操作を足すことになる」ため分けず、コミットだけ分けた。

human レビューは 0 件（レビュー・レビューコメントとも 0）。CI は視覚差分が 1 度だけ赤（意図した差分で `visual-approved` ラベルにより通過）。**指摘はすべてサブエージェント（`plan-reviewer` / `implementation-reviewer`）から出た。**
