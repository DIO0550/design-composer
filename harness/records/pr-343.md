# PR #343 編集画面のストーリーに高さの決まった器を与えて下端のドックを撮影範囲に入れる

- マージ日: 2026-08-28
- 関連 Issue: #322
- 差分規模: 2 ファイル / +19 -1

## ゴールと結果

`OpenedDocumentEditor` のストーリーを高さの決まった親の中で描き、キャンバス下端のドック
（エラー一覧 + ツールバー）を VRT の 1280×720 の撮影範囲に入れる。達成した。

4 ストーリーとも `scrollHeight` 720 / `scrollWidth` 1280 に収まり、VRT は Changed 4 /
Passed 134 で、意図した 4 本だけが動いた。ミューテーション 4 本（`bottom-4` / `gap-3` /
`CenterPane` の `relative` / decorator ごと外す）で、いずれも閾値 0.002 を超える差分が
出ることを実測した。

ゴールは変えていないが、**達成手段は計画から大きく変わった**（後述の手戻り）。

## 手戻り

**計画の中心を丸ごと捨てた。** 当初の計画は「`EditorScreen` の class を写した器を
`__stories__/` のモジュールへ切り出し、写される側（`editor-screen/__tests__/`）に突き合わせ
テストを置く」で、既存の先例（`LeftPaneShell` #304 / `RightPaneShell` #300 +
`editor-layout.pane-width.test.tsx`）に倣ったものだった。

`plan-reviewer` の指摘 1〜4 を受けて、**写しという設計そのものが正当化できていない**と分かった
（本体はツールバーを挟むので「同じ器」ではなく、先例の Why not もこの位置では成立しない）。
ツールバーを含めないと決めた時点で器は `EditorScreen` の写しではなくただの「高さの決まった箱」に
なり、写しが無いのでずれようがなく、突き合わせテストも要らなくなった。結果として
新規ファイル 2 つ（器 + テスト）が消え、`meta` の decorator 直書き 1 箇所に畳まれた。

実装後にも 1 往復あった。`implementation-reviewer` の指摘 6・7 で**自分が書いたコメントの
事実誤認**が見つかり、未 push だったのでコメントとコミット本文を `--amend` で同時に直した。
指摘 9 で `overflow-hidden` を外し、外した状態で 4 ストーリーを測り直して同一であることを
確認してから push した。

測定でも 1 度誤った。ミューテーションのために作り直した `storybook-static/` が
`bottom-4` を落としたビルドのまま残っており、そのまま次の測定に使うと本番と違う数字が出る。
gitignore 対象なので `git status` には現れない。削除して作り直した。

## うまくいったこと

- **ミューテーションを実測してから doc を書いた。** `CenterPane` の `relative` を落とす
  ミューテーション（`plan-reviewer` の指摘 12 が「直すか決めろ」と言ったもの）を実際に走らせ、
  器を入れたあとも `編集で作った不正がある編集画面` が 0.0114 で赤になることを確認できたので、
  **doc を直す必要が無いと実測で決められた**。推測で書き換えずに済んだ
- **VRT の結果を事前に予測して、予測と突き合わせた。** Changed 4 / Passed 134 は事前に
  PR 本文へ書いた予測と完全に一致した。**Passed が 134 であること**が「decorator が他の
  ストーリーへ影響していない」ことの確認になっており、赤 4 本だけを見るより情報量が多い
- **サブエージェントの事実主張を自分で裏取りした。** import 規約違反は `classify()` を実際に
  走らせ、ツールバー 47px は dev サーバーで測り、日本語フォントは `fc-list` で数えた。
  3 件とも指摘が正しかったが、確かめる手順を踏んだことで数値を PR に書けた

## 規約への反映

無し。14 件のうち 11 件は既存ルールに対応があり、いずれも 1 回目のため
（`AGENTS.md`「ルールに書かれていない指摘が 2 回以上出たら規約の抜けとして扱う」）。

`分類: なし` の 3 件（指摘 10・11・14）は、いずれも「コード内コメント以外の場所
