## ゴールと結果

ゴールは「`property-panel/index.tsx`（1,017 行）に同居していたまとまりを、それぞれ独立して読める単位へ割る。見た目・振る舞い・公開 API・story id・テストの観点は 1 つも変えない」。達成した。8 サブフォルダへ分け、`index.tsx` は 166 行になった。

human レビューは 1 件（「story もそれぞれ作って欲しいです」）。CI は 2 つの head でいずれも 1 回目から全チェック success で、視覚差分は Changed 0（1 回目 Passed 105 / ストーリー追加後 New 27 + Passed 105）。**指摘の大半はサブエージェント（`plan-reviewer` 9 件 / `implementation-reviewer` 8 件）から出た。**

**この回の中心は 2 つ。** 1 つは、移動の忠実性は `implementation-reviewer` が機械検証（旧ファイルと新 9 ファイルの連結を、import 行・`export` 接頭辞・空行を除いた行の多重集合で比較 → コード行の増減 0）で確かめており、**指摘がすべてコメントと境界の話に収束したこと**。もう 1 つは、**計画で却下した「サブフォルダごとのストーリー」が、人間のレビューで採用へ反転したこと**（指摘 9）。却下理由が一時的な事実に依っていることは `plan-reviewer` が先に指摘しており、そのときは別 Issue（#296）へ切り出す形で答えていた。

## 手戻り

3 件。

1. **ストーリーの追加**（指摘 9）。計画で却下 → #296 へ切り出し → 人間レビューで反転 → 同じ PR へ 27 本追加。指摘から実装まで 1 往復ぶんの手戻り。#296 は取り込み済みとして閉じた
2. **`shorthand-row` の import**。コンパニオンオブジェクト（`PropPairControl` / `PropShorthandControl`）を型と値で別々に import して別名を付けたが、このリポジトリでは型と値が同名で 1 つの import で足りる。**typecheck には出ない（動く）形**で、書いた直後に自分で気づいて戻した
3. **`prop-field` の行数**。計画の完了条件（サブフォルダ 300 行以下）に対し、最終的に 302 行になった（`FieldBinding` の doc を足したため）。2 行の超過で分割し直す判断はせず、超過したことを記録に残す側にした

## うまくいったこと

- **VRT を手元で先に回した。** `git worktree` で `origin/main` を並べて両方の Storybook をビルドし、105 枚のスクリーンショットを sha256 で突き合わせて 0 差分を確認してから push した（`odiff` サーバがこの環境で起動しなかったため比較は sha256）。CI の視覚差分は 2 つの head でいずれも 1 回目から Changed 0 で、赤くしてから直す往復が無かった
- **テストファイルを 1 文字も触らずに済ませた。** `__tests__/` の import 先がすべて `../index` だったので、再 export だけで 80 件が動いた。「観点が減っていない」ことを差分そのもの（`git show --stat` に `__tests__/` が出ない）で示せた
- **`implementation-reviewer` の機械検証。** 旧ファイルと新 9 ファイルの連結を行の多重集合で比較して「コード行の増減 0」を示しており、移動の忠実性についてはレビューで読む必要が無くなった。移動系の差分ではこの確認を先に頼むとよい
- **サブエージェントが対象ファイルを書き換えたまま返す事故が無かった**（両方とも `git status` は clean）。`implementation-reviewer` はミューテーションを入れたが、すべて元へ戻したうえで返している

## 規約への反映
