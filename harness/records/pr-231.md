# PR #231 [schema] padding を 4 方向個別（T / R / B / L）にする

- マージ日: 2026-08-16
- 関連 Issue: #166（分割先 #230）
- 差分規模: 19 ファイル / +208 -93

## ゴールと結果

Box の padding を `paddingX` / `paddingY` の 2 軸から `paddingTop` / `paddingRight` /
`paddingBottom` / `paddingLeft` の 4 方向個別へ置き換える。達成した。

**Issue 本文が「決めること」で構成された仕様（`docs/03-schema.md`）の判断 Issue だったため、
着手直後に止めて判断を仰いだ。** 拠り所を実際に当たったうえで、UI 案の padding セルが
`▾` も解決値も持たない半幅 2×2 であること、`libs/document-migration` が枠だけで登録ステップ
0 件であること、「4 セルだけ解決値を出さない」は `prop-control` が禁じる prop 名分岐でしか
書けないことを確かめてから、選択肢と根拠を Issue へ書いた。着手時点でセッション URL を
Issue へ残し、判断待ちのコメントにも併記した。

回答（「Figma だと個別と垂直/水平をボタンで切り替えるからそうしたい」）を得て、
**データモデルは 4 方向・2 軸表示はパネルのビュー**と確定させ、パネルの 1 行クラスタ表示と
切り替えボタンを #230 へ分割した。

**ゴールの範囲が途中で縮んだ。** 初版は formatVersion を 2.0 へ上げてマイグレーションを
登録していたが、レビューで「まだファイル一切作成とかしてないから、バージョンはまだ更新
しなくていい」と指摘を受け、版まわりを丸ごと取り下げた（指摘 1）。取り下げにより差分は
42 ファイル / +1003 -157 から 19 ファイル / +208 -93 へ縮んだ。

人によるレビュー指摘は 1 件（指摘 1）。CI の失敗は 0 件。以下の指摘 2〜10 はすべて
`implementation-flow` のフェーズ 4 / 6 のサブエージェント検証で出たもので、
**指摘 2〜9 は取り下げた範囲（マイグレーション・版モジュール）に対するもの**。
