# PR #530 🐛 運んだ直後の click を枠ではなく 3 ペインの器で飲み込む

- マージ日: 2026-09-14
- 関連 Issue: #404
- 差分規模: 8 ファイル / +124 -24

## ゴールと結果

Issue のゴールは「落とせる親が無い場所でノードを離しても、そのあと最初のクリックが選択に使われる」。

**実機で測ったらこの前提が崩れた。** Storybook（`OpenedDocumentEditor / 絶対配置のノードがある編集画面`）を Chromium で操作したところ、`dropped` は次の `pointerup` でも解ける（`NodeDrag.release` は `dragging` 以外を `idle` にする）ため、実際のマウス操作では「次のクリックが消える」症状が出ない。残っていたのは「`pointerup` を伴わない `click`（＝離した直後にブラウザが投げる 1 回）が飲み込まれる」ことだけだった。

ゴールを「飲み込む状態が、飲み込む相手の `click` より長く残らないようにする」へ読み替え、Issue が「先に決める必要がある」としていた点は **落とせなかったときも `click` は通さない**（運んだ以上クリックではない）と決めた。`NodeDrag.release` の条件は main のまま、飲み込む受け口を `ArtboardFrame` の `onClick` から 3 ペインの器（`dragHandlers` の付け先）へ移した。

リサイズ（`NodeResize`）に残る同じ形の穴は #534 へ分けた。
