## ゴールと結果

ゴールは「キャンバスの直接操作一式が `features/canvas/` として独立し、`EditorState` ではなくドキュメントと選択の対（`DocumentSelection`）・トークンの対（`TokenSelection`）・凍結しているかの 3 値で描ける」。達成した。#174 の feature 分割の最後（#250 tokens・#251 assets・#253 sidebar に続く、最大かつ `EditorState` の使用が最も広い領域）。

移したのは 12 モジュール 75 ファイル（`artboard-canvas` / `node-insert-toolbar` / `canvas-view` / `node-drag` / `node-drop` / `node-resize` / `text-edit` / `use-canvas-view` / `use-node-drag` / `use-node-resize` / `use-text-edit` / `CanvasPointer`、およびテストヘルパー 2 本）。`src/domains/document-selection` に `names` を、`node-drag` に `carriedTemplate` を足し、`EditorState` から `isCurrentArtboard` / `selectedNames` を剥がした（41 → 38 メソッド）。`canvas → editor` の import は 0 件、`editor → canvas` の deep import も 0 件（残るのは公開 API と `__tests__/` のヘルパー 2 本だけ）。

human レビューは 0 件（reviews 0）。CI は 6 チェックすべて 1 回目で success、視覚差分も 0 changed（移した story は New 34 / Deleted 34 として扱われ比較されない）。**指摘はすべてサブエージェント（`plan-reviewer` 12 件 / `implementation-reviewer` 10 件）から出た。**

テストは 350 ファイル / 2366 テスト。

**この回の中心は 2 つ。** 1 つは計画の件数・ファイル表がまた実例に当たっていなかったこと（指摘 1〜5。`plan-scope-verification` が 3 件）。もう 1 つは、**同じ差分の中でコメントの根拠が壊れたこと**（指摘 16〜19）。とくに `compiled` の memo は「対はレンダーのたびに組み直すので落ちない」と書いたが、同じ差分で呼び出し側を `useMemo` にしたため前半が偽になり、後半（「テストでも視覚差分でも落ちない」）は実測すると 3 件落ちた。書いた時点では正しかった Why が、同じ PR の別の変更で嘘になる形。

## 手戻り

- **1 件。** テストの書き換えで `EditorState.create(DesignDocument.create({...}))` の外側だけを外したとき、閉じ括弧の対応を崩して `artboard-canvas.multi-selection.test.tsx` が TS1109 になった。`pnpm run typecheck` で検出し、その場で修正
- **計画からの変更 2 件。** ①`EditorState.selectedNames` を「据え置く」→「削除する」（指摘 16 で撤回）②`carriedTemplate` の帰属を `NodeDragControl` だけ → `NodeDrag`（ドメイン）にも置く（指摘 6）。どちらも Issue #256 に理由を追記した
- 環境面: この作業環境には CJK フォントが無く、Storybook の撮影前に `fonts-noto-cjk` の導入が必要だった（入れないと日本語が豆腐になり、VRT の capture がフォント検査で止まる）

## うまくいったこと

- **移動と props の付け替えを 1 コミットに保った。** 移動だけを先に入れると `canvas → editor` の import が中間コミットに残り、この Issue が消そうとしている辺を一度作ることになる。分けない理由をコミット本文に書いた
- **`plan-reviewer` の実測がそのまま計画の訂正になった。** 件数・呼び出し側・テストの観点をすべてコードに当て直して返してきたので、実装前に 5 件の数え違いを潰せた
- **`implementation-reviewer` のミューテーションで、コメントの主張を 3 件反証できた。** とくに `compiled` の memo は「落ちない」と書いた側が実際には 3 件落ち、守っている対象（性能ではなく振る舞い）を取り違えていたことが分かった
- 前回（#253）と同じ形で `DocumentSelection` を受け取る設計に揃えられたので、キャンバス側で新しい対の型を作らずに済んだ
