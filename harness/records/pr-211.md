# PR #211 選択中トークンの参照元をキャンバスで破線にし、下端に本数の帯を出す

- マージ日: 2026-08-14
- 関連 Issue: #147（`reveal in tree` は #209 へ分離）
- 差分規模: 17 ファイル / +1071 -19

## ゴールと結果

選択中のトークンを参照しているノードがキャンバスで破線で囲まれ、下端に
「トークン名 + 破線が掛かっているノード数」の帯が出るようになる。達成した。

**#147 の本文には「実装前に決めること」が 6 点残っていた。** 推測で埋めず一度停止して
選択肢と根拠を Issue に出し、回答を得てから着手した。判断待ちに当たっていたのは
`reveal in tree` だけだったので、そこを #209 へ分離してこの回のスコープを絞った。

`test-behavior` 1 件 / `duplication-test` 1 件 / `naming` 1 件 / `なし` 1 件。

`comment-mismatch` が 1 つの PR で 3 件出ているが、**介入の判断と集計は `harness-growth` の
管轄**なので、ここでは数えず記録に留める。3 件はいずれも「書く前に確かめれば防げた事実の主張」
という同じ形で、確かめた相手が違う（雛形のトークン参照が 2 件、ミューテーションの結果が 1 件）。

**この回の介入（`count.sh` が数える行。棚卸しルーティンによる事後追記）:**

`test-behavior` は pr-171 で rules 層へ介入済みだが、その後 5 件再発（通算 39 件。
pr-173 の指摘 12・13、pr-185 の指摘 7、pr-192 の指摘 5、この記録の指摘 1）し飽和していた
（`.claude/skills/harness-growth/SKILL.md`「2c. 介入後 5 回以上」）。直近の記録を並べると、
原因の性質が異なる 2 種が 1 つのタグに畳まれていた。

| 新語彙 | 内容 | 件数 |
| --- | --- | --- |
| `test-default-input` | 確かめた入力が既定値と一致しており、規則を壊すミューテーションでも既定値側で通ってしまう形 | 2（pr-173#12・pr-192#5） |

形で、既存ルール（`implementation-review.md`「最後の1つはhappy-domでは落とせない」）どおり
コメントで対処済みのケース。1 件しか無く上の 2 種のどちらにも当たらないため、新しい語彙は
割らない（`harness-growth`「1件しか出ていない分類は何もしない」）。

**採らなかった置き場所と理由（両方とも）:** フック化は成立しない。「確かめた入力が既定値と
一致しているか」「差分の中心の判断をすべて数え切れているか」はどちらも差分の意味理解が要り、
文字列・AST 一致では判定できない（誤検知がフック全体の信用を落とす経緯は pr-171 / pr-192 と
同じ）。段取りが複数ステップに増えるわけでもないので新しいスキルも作らない。層は据え置き、
`implementation-review.md`「テストが守っているかの観点」の該当箇所へ、それぞれの確認手順を
具体化した観点を追加した。
