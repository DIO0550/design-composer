## 指摘

### 1. 選択が外れる操作が「見ている artboard の切り替え」になっていた

- 分類: `plan`
- 出どころ: 自己修正（実装検証のサブエージェント）
- 内容: `currentArtboard` を「選択 → 載っている artboard / 選択なし → 先頭」で導出した
  ため、`selectedName` が `none` になる操作がそのまま表示の切り替えになる。プロパティ
  パネルの「選択を解除」1 クリック、ノードの削除、その直後の undo の 3 経路で、
  見ている artboard が 1 枚目へ飛ぶ。変更前は全 artboard がツリーに出ていたので
  この飛びは存在せず、**この PR で入った振る舞いの後退**
- 既存ルール: なし。`rules/coding.md`「不正な状態を型で表現できなくする」は
  「持たずに導出する」を後押しするが、**導出の入力が失われたときに何が起きるか**は
  扱っていない。`plan-review.md` の観点にも無い
- 次にどう防ぐか: **`plan` は通算 8 回目。** ただし今回の中身（導出の入力が失われる）は
  過去の 7 件が言い当てていない新しい観点なので追記する。「状態として持たず導出する」と
  決めた計画では、**導出の入力が失われる操作を数える**を `plan-review.md` に足す。
  今回の修正自体は #112 で判断を仰いでから別 PR で行う

## 規約への反映

この回で 2 回以上に達した分類は 4 つ。置き場所は `harness-growth` の Step 4 に従い、
強制力の強い順（フック → 新しいスキル → 既存スキルの観点 → `rules/`）に検討した。
**上の番号を採らなかった理由も残す。**

| 分類 | 回数 | 反映先 |
| --- | --- | --- |
| `plan` | 8（うち今回 1） | 既存スキルの観点（#3）— `plan-review.md` の妥当性の観点に「状態を持たず導出すると決めたなら、導出の入力が失われる操作を数える」 |
| `duplication` | 4（うち今回 2） | 既存スキルの観点（#3）— `implementation-review.md` に「重複の観点」を新設 |
| `utils-form` | 2（うち今回 1） | 既存スキルの観点（#3）— `plan-review.md` の妥当性の観点に「同じ操作が既にどこかに無いかを探したか」 |
| `test-behavior` | 7（うち今回 2） | `rules/` の表現を直す（#5）— `rules/testing.md`「assert は『落ちうるか』…」に既定値・フォールバックの場合の NG/OK を足す |

**なぜフック（#1）にしなかったか。**

- `plan` / `duplication` — どちらも判定が判断。「導出の入力が失われるか」は計画の
  文章を読んで初めて決まる。「同じ処理が 2 箇所」も、同じ関数を複数箇所から呼ぶこと
  自体は正常なので、文字列一致では偽陽性しか出ない（pr-141 の `duplication` と同じ結論）
- `utils-form` — **`array[0]` の直書きを拾うフックを具体的に検討した。** 成立しない。
  `ArrayEx.first` の実装自身が `array[0]` を書いているし、添字が計算値のとき
  （今回の修正後の `document.artboards[index]` がまさにそれ）は正当。
  `check-test-rules.sh` のように対象を絞る条件が立たない
- `test-behavior` — 「その assert は落ちうるか」は**ミューテーションテストを回せば
  機械判定できる**（実際、今回はそれで直ったことを確かめた）。ただし全テストを
  変異ごとに回すので CI 時間が跳ね、フックとして毎回走らせるには重すぎる。
  **フックにできないのではなく、費用が見合わない**ので採らない

**なぜ新しいスキル（#2）にしなかったか。** 4 件とも毎回踏む段取りではなく、
既存フェーズで見る観点が 1 つ増えただけ。計画の検証（フェーズ 4）と実装の検証
（フェーズ 6）は既にあり、そこへ足せば必ず通る。

**なぜ `test-behavior` だけ #3 ではなく #5 か。** ルール自体は `rules/testing.md` に
既にあり（PR #124 で足したもの）、今回は**それを読んだうえで踏んだ**。観点を新しく
足すのではなく、踏んだ形（既定値と同じ答えになる入力を選ぶ）を NG/OK の対比で
書き足すのが正しい層と判断した。

`naming` / `illegal-state` / `over-guard` / `logic-ownership` / `type-vocabulary` も
2 回以上だが、今回の指摘には含まれないため触れていない。

`なし` は 9 件目。今回の中身（`aria-current` が同じペインの中で 2 つの意味を持つ）は
過去のどれとも重なっていないので記録のみとする。
