# PR #1256 ドキュメント I/O コマンドが受け付ける .dcmp を、利用者が選んだものに限る(許可リスト)

- マージ日: 2026-11-02
- 関連 Issue: #1155
- 差分規模: 54 ファイル / +2086 -360

## ゴールと結果

ゴール: webview がドキュメントの 4 コマンド(load / save / watch / unwatch)に渡せる `.dcmp` は、利用者がダイアログで選んだ・ドロップした・その記録に残っているものに限られ、それ以外は Rust 側で `notChosen` として拒否される。再起動後も最近使ったファイルからは開ける。達成した(実機での確認はオーナー側)。
- 着手時に Issue 本文が「層の移動を含むので着手前にオーナーの判断を仰ぐ」と明記していたため停止し、Q1〜Q4 を「推奨で」で再開。計画の検証後に Q5(更新後最初の起動の選び直し)・Q6(文言)でもう 1 度停止した
- 照合前の正規化・シンボリックリンク・UNC は #1240 に分けた。`notChosen` の項目を最近使ったファイルから外すかは #1157 に任せた
- CI は `cargo test` を走らせない。この環境に GTK / WebKit の開発ライブラリを入れて手元で走らせた(最終 142 件)

GitHub 上の人のレビューは 2 件(`get_reviews` のオーナーの本文 1 件と、`get_review_comments` の行コメント 1 件)。`copilot-pull-request-reviewer[bot]` のレビューは「具体的な欠陥は無し。CI が cargo test を走らせず実機確認が要る」で、指摘は無い。`get_comments` は `github-actions[bot]` の 3 件と自分のテスト表 2 件。CI は最初の head(1705b3d)とレビュー対応後の head(df17299)の両方で全部成功し、VRT の差分は 0(新しいストーリーが 2 件)。
