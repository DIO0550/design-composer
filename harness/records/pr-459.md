## ゴールと結果

`layout: free` の器（Box / artboard）の中でも、絶対配置の子をキャンバスでドラッグして
**その器を親にしたまま**座標を置き直せるようにする。

**達成した。** 着手時に一時テストで再現を実測してから計画へ入り、Issue の「現象」が実物と
一致することを確かめている（`free` の Box: `parentName` が `panel` → `home` へ変わり座標も
書き直される / `free` の artboard: `onRepositionNode` の呼び出しが 0 件）。

ゴールの範囲は計画の途中で 1 つ広がった。`free` を座標経路の候補へ通すと **`free` の器へ
外から絶対配置の子を運び込む経路**も同時に開くが、当初のゴール文（「その器を親にしたまま」）は
これを覆っていなかった。`plan-reviewer` の指摘 10 でスコープ内と決め、テストで固定した。

人のレビューは 0 件（`get_review_comments` / `get_reviews` / `get_comments` の 3 つとも引いた。
`get_comments` の 3 件はすべて `github-actions[bot]`）。CI の失敗も 0 件。

### 1. 雛形のテストを、production では通らない経路へ割り当てていた

  実際に動かして確かめる）
- 次にどう防ぐか: 今回は記録のみ。`claim-verification` スキルは「書いた主張」を対象にしており、
  **テストケースの割り当て先**は主張の形を取らないので今の手順では拾えていない
