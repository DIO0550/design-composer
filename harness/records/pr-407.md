# PR #407 キャンバスで親をまたいで運んだら親を付け替える

- マージ日: 2026-09-05
- 関連 Issue: #388（分離先: #404 / #405 / #406）
- 差分規模: 33 ファイル / +1512 -596（3 コミット）

## ゴールと結果

#388: 絶対配置のノードをキャンバスで運んで別の親の上で離すと、その親の子に付け替わり、画面上の
位置が変わらないよう新しい親から見た座標へ直して書かれる。`RepositionLimit` のクランプを外し、
はみ出し配置がドラッグで作れる。

達成した。ただし**マージまでに人のレビューが 2 回入り、そのたびに push している**。2 件とも
「運んでいる最中の見え方」で、初回の差分は付け替えの結果（離したあとの座標・親）しか見て
いなかった。

- 1 回目「キャンバスの外に出すときに、裏側に回るせいで、移動てきてるのかわからない」
  → 運んでいる間だけ包んでいるものの切り取りを解き、掴んだノードを前に出す（`bb056b8`）
- 2 回目「一時的に Canvas 外にマウスが移動すると、移動しようとしてたやつがもとの位置に表示される」
  → 落とせるかどうかと追従するかどうかを直和で分けた（`aa1fa1c`）

`#405`（運んでいる間ノードが見えない）は 1 回目の対応で解消したので、実測を添えて閉じた。

### 1. 運んでいる最中に何を運んでいるのか分からなかった

- 分類: `なし`
- 出どころ: `レビュー（人）`
- 内容: 親をまたいで運んでいる間、掴んだノードが画面のどこにも映らない（artboard の
  `overflow:hidden` に切り取られ、切り取られない向きでも隣の artboard の面の裏へ回る）。
  **表示確認では運んでいる最中の絵を実際に撮っていたのに、そこにノードが映っていないことを
  見落としていた**。撮った絵で確かめたのは「落とし先の枠が出るか」「離したあとの座標」だけ
- 既存ルール: なし（`rules/ui-verification.md`「主要なユーザー操作フローを通しで確認する」は
  操作の**結果**を見よ、とは読めるが、**操作の最中の見え方**を見よとは書いていない）
- 次にどう防ぐか: 今回は記録のみ
