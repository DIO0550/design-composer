# PR #726 doc コメントの検査をコンパニオンオブジェクトのメソッドまで広げる（追加行だけブロック）

- マージ日: 2026-09-23
- 関連 Issue: #719
- 差分規模: 13 ファイル / +479 -64

## ゴールと結果

ゴール（`Foo.bar()` の形のメソッドにも doc の検査が効き、新しく書いたメソッドが doc 無しのまま
push / CI を通らない）は達成した。`missing-doc-comments.py --include-methods` と、追加行だけを
止める `check-added-doc-comments.sh` を pre-push と CI の `lint-suppress` ジョブへ配線した。
`--all` の既定は変えていない（既存の抜けは #720）。

**既存の抜けの件数が Issue 本文とずれた。** 本文は 303 件（PR #718 のマージ前の値）で、着手時点の
退避差分では 298 件。退避差分が改行したシグネチャ・式本体のアロー関数を取りこぼしていたのを
直した結果、**370 件**（doc 無し 110 / 項目の欠け 260）になった。#720 はこちらに合わせる必要がある。

## 手戻り

- **計画を 1 回作り直した**（1・3・4）。退避差分のメソッドの見分け方をそのまま使い、
  件数も 298 件のまま書いていた。`plan-reviewer` の指摘で 370 件に数え直し、#720 の件数も
  ずれることを Issue に書いた
- **オブジェクトの閉じ方を作り直した**（10・11）。計画では波括弧を数える形で「文字列の中の
  括弧は miss」としたが、`implementation-reviewer` の指摘で 1 列目の `}` で閉じる形へ変え、
  miss を 1 つ消した
- **判定表を 2 回増やした**。計画時 9 行 → `plan-reviewer` 後 14 行 → `implementation-reviewer`
  後 18 行。`check-added-cases.sh` も 6 行 → 7 行
- **push 前にコミットメッセージを 1 件直した**（15。未 push のブランチなので amend）
