- マージ日: 2026-08-28
- 関連 Issue: #344
- 差分規模: 7 ファイル / +122 -20

## ゴールと結果

ストーリーの器が実画面と食い違っていることに、人が偶然気づく以外の手段で気づけるようにする。

- 向き 1（撮影範囲からはみ出す）は達成。`capture` が全ストーリーの実寸を読み、超過があれば
  ストーリー名・id・実寸を並べて落ちる。CI 実測で main は 138 ストーリー / 超過 0 件、
  #322 の状態を作り直すと 4 本を挙げて exit 1
- 向き 2（潰れる）は**既知 1 件の解消のみ**。`EditorLayout` のストーリーへ器を与えたが、
  次の潰れを見つける手段は増えていない（「潰れている」の閾値が立てられないため機械的検出は却下）
- **Issue が立てた仮説が実測で崩れた。** 「器を与えれば `凍結した3ペイン` が `FrozenPaneClass`
  の消失を捉える」は成立せず（器の有無で 0.0004 のまま・閾値 0.002）、doc の書き換え先を
  `OpenedDocumentEditor / ファイルが不正になった編集画面`（0.0031）へ変え、残りを #346 へ分離した

## うまくいったこと

- **判断のすべてを実測に載せた。** Issue の仮説を疑う根拠も、doc に書く名前も、
  「この PR の視覚差分は 0 件」も、すべて CI と同じ条件（threshold 0.1 / antialiasing /
  max-diff-ratio 0.002）で測ってから書いた。CI の結果（0 changed / 138 passed）とも一致した
- **共通化のあと、絵が変わっていないことを全 138 ストーリーで確かめてから push した。**
  リファクタで VRT を赤くして 1 サイクル失う形を避けられた
- **検証エージェント 2 本が、どちらも自分では気づけない形を捕まえた。**
  `plan-reviewer` の 12 件は計画段階で潰れ、`implementation-reviewer` の 11 件は
  PR に出る前に潰れた。人のレビューは 0 件（3 メソッドすべてで確認）で、すり抜けは無かった
- **色差の閾値の性質を測って知れた。** 白と極薄い灰色（`bg-gray-100`）の面積差は
  素のバイト比較では 0.003 出るのに、CI の閾値では 0 件になる。VRT の結果を読むときの
  前提として、次の回に効く
