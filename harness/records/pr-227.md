## ゴールと結果

インスタンスを選んでいるとき、右ペインの `Select all N instances` を押すと同じ部品を指す
インスタンスがまとめて選ばれ、ツリーとキャンバスで強調される。複数選択の間は右ペインが
件数だけを出し、編集操作は成立しない。達成した。

**Issue 本文が「選択を複数持てるようにするかどうか自体が未決」と明言していたため、着手直後に
止めて判断を仰いだ。** 拠り所を実際に当たったうえで、`docs/Design Composer.html` は
`Select all` が 2 箇所（ボタンと説明文）しか無く**複数選択後の画面を 1 枚も描いていない**こと、
`docs/06-ui.md` は「選択」節が 2 行で編集操作の一覧がすべて単数であることを確かめてから、
選択肢と根拠を Issue へ書いた。回答を得て 5 論点（選択の表現 / 右ペイン / 編集操作 / 分割 /
仕様書追記）を確定させ、計画へ進んだ。

着手時点でセッション URL を Issue へ残した。判断待ちで止まったコメントにも併記した。

## 手戻り

計画から外れたのは 6 点。理由は Issue #161 のマージ後コメントに表でまとめた。
**実装中に追記できておらず、マージ後にまとめて書いた**（`implementation-flow` フェーズ 5 は
「外れた時点で Issue に追記する」としている）。

主なもの:

- **`EditorState.sourceInstanceCount` を足す計画をやめた。** `Option<number>` を返すため
  消費側で `Option.unwrapOr(..., 0)` が要り、rules/coding.md「失敗を握りつぶして既定値へ
  フォールバックしない」に触れる。`prop-control` が `Node.isRef` の枝の中で
  `DesignDocument.collectInstanceNames(...).length` を直接数える形へ変えた
- **`SelectionControls.sourceName` を削除して `EditorState.sourceName` へ移した。**
  計画は `multiple` 枝に `source` を持たせて据え置く形だったが、`left-pane` は `state` を
  持っているので直接呼べる。移した結果、呼び出しが 0 になった `SelectionControls.sourceName`
  を消した
- **`SelectionState.fromName` を足した**（計画に無し）。`select` と `selectInnermost` が
  同じ変換を書いており、2 箇所に現れた時点で共通化した
- **キャンバスの「複数選択中はハンドルが出ない」テストを書かなかった**（計画では書く予定）。
  まとめて選べるのはインスタンスだけで、インスタンスにはもともとハンドルが出ないため、
  何を壊しても通るテストになる。理由をテストファイルのコメントに残した
- `opened-document-editor/__tests__/setup.tsx` に `document` の任意引数を足した（計画に無し）。
  通しテストに「同じ部品を指すインスタンスが 2 つある」ドキュメントが要るが、
  `SampleDocument` は 1 つしか持たない
