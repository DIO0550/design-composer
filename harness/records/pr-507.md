## ゴールと結果

`src/utils/Option.ts` を除いて、`Option` の在／不在の判定を `Option.isSome` に揃え、判別子
(`option.some`)の直読みを 0 件にする。振る舞いは変えない。達成した。

Issue 本文の「404 箇所 / 137 ファイル」は `grep` の行数で、実際の直読みは 406 箇所 / 134 ファイル
(`src/utils/Option.ts` の 7 箇所を除いて 399 箇所 / 133 ファイル)。着手時に数え直して Issue へ
書き残してある。差分が 134 ファイルなのは、`Option.ts` の doc 1 行を直したため(指摘 2)。

スコープ外に置いた `Result` 側(`isOk` / `isErr` と `.ok` の直読み 115 箇所)と、直読みを禁止する
検査の追加は #506 へ分けた。

## うまくいったこと

- **一括置換を逆変換で検算した。** 変更後の全 134 ファイルで `Option.isSome(EXPR)` → `EXPR.some`
  に戻し、空白・末尾カンマ・import を正規化して base と突き合わせた。食い違ったのは意図した 2 件と
  biome が JSX に付けた括弧 2 件だけで、**式の範囲の取り違えが 0 件であることを目視ではなく機械的に
  示せた**。399 箇所を 1 つずつ読む代わりになる
- **codemod が踏み外しやすい場所を選んでミューテーションした。** 再フォーマットが掛かった 5 サイト
  (＝ 1 行に収まらず biome が折り返した箇所)で `!` を反転させ、それぞれ 3〜48 件のテストが落ちる
  ことを実測した
- **計画の段階で 1 度試走してから計画を書いた。** codemod を流して typecheck / test / biome まで
  通したうえで `git checkout -- src/` で戻し、実測値だけを計画に載せた。おかげで
  `plan-reviewer` が「件数・内訳・前提はほぼ完全に正確」と検算できる形で渡せた
- **数の主張を書くたびに数え直した。** 指摘 10 の 2 件は `plan-reviewer` へ渡す前に自分で捕まえた
