## ゴールと結果

`absolute` のノードを運んでいる間、寄せが効いた辺をガイド線で見せる（Figma のスマートガイド相当）。

**達成した。** Issue が「実装前に確認する」と指定していた線の色・太さは、選択肢と根拠を出して回答を
待ってから実装に入った（`#d13438` / 2px 中心合わせ）。

**線を出す条件は Issue 本文から意図的に離れた。** Issue は「寄せ量が 0 でない軸だけ」と書いていたが、
寄せ量は毎回の `pointermove` で吸い付く**前**の行き先から計算し直すため、ぴったり揃った瞬間だけ 0 に
なる。0 の軸を外すと**いちばん揃っている瞬間に線が消える**。現行の `toOffset` が「届く辺が無い」と
「既に揃っている」を同じ `{x:0,y:0}` で返すことを、2 つの入力を並べて実行し `toEqual` で一致することを
確かめたうえで「揃う辺が見つかった軸」に変えた。

人のレビュー・CI の失敗はどちらも 0 件（CI は 2 コミットとも一発で緑、VRT も差分 0）。指摘はすべて
サブエージェント由来。

## 手戻り

1. **計画の作り直し 1 回。** 指摘 1（返す型から寄せ量が計算できない）で、返す形を
   「揃った辺の並び」から「寄せ量 + 描く矩形」へ組み直した。実装前だったのでコードの手戻りは無い。
   このとき指摘 6・12 も一緒に解消している（太さは定数へ / `Range` が不要に）。

   `side-snap` / `node-drag` / オーバーレイと、それらのテスト・story を書き直した（2 コミット目）。
   計画では「配列のまま」と決めていたので、計画から外れた箇所にあたる。
3. **index キー案の撤回 1 往復。** 指摘 22 の対応で `key={index}` を書いたが、biome の
   `noArrayIndexKey` に触れ、抑制コメントは CI（`lint 抑制コメントの追加チェック`）が弾くため

## うまくいったこと

- **仕様から離れる判断を、実行結果で裏付けた。** 「寄せ量 0 の軸を外すと、いちばん揃っている
  瞬間に線が消える」を、既存 `toOffset` に 2 つの入力を並べて実行し確かめてから Issue へ書いた。
- **ミューテーション実測で、新しいテストが 1 件を除きすべて落ちた**（落ちなかったのは
  `pointer-events-none` の 1 件で、それ自体が指摘 23 になった）。
- **VRT の死角を実ブラウザで埋めた。** 線は運んでいる最中にしか出ないので、Storybook を立てて
  playwright でポインタを押し下げたまま撮影し、揃えた辺に線が出て離すと消えることを確認した
  （設計を変えた 2 コミット目のあとにも同じ手順で再確認し、同じ値になることを見た）。
- **CI は 2 コミットとも一発で緑**（VRT も差分 0 / 新規 2）。push 前の検査を `&&` で連ねず
  1 つずつ実行した。
