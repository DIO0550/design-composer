この 3 つの語彙は、`なし` として溜まっていた 14 件を `harness-growth` の「逃し弁」で
グルーピングして昇格させたもの（pr-233 時点）。

## `rules-consistency` — 規約自身が矛盾している / 例で逆の答えを出す

**いちばん多い（4 件）。** 規約を書き足すときに、その規約が既に持っている記述・例と
突き合わせていない形。規約は増える一方なので、足すたびに検算が要る。

| 起きたこと |
|---|
| 規約に書いた判断基準が、**同じ規約の前の節と矛盾していた** |
| 規約に書いた判定文が、**規約自身が挙げている例で逆の答えを出した**（「キーを値へ置き換えても意味が変わらないか」が `LeftPaneViewLabels` で逆になる） |
| 規約の表に、`src` で最も多いキーの種類（型のフィールド名）の行が無かった |
| 規約の Why not を、**同時に直されつつあった一時的な事実**に置いた（直った時点で理由が嘘になる） |

確かめ方は 3 つ。`harness-growth` の Step 2 に手順として入っている。

1. **足す節の判定文を、同じファイルが既に挙げている例すべてに当てる。** 1 つでも逆の答えが
   出たら判定文が誤っている
2. **足す節と、同じファイルの前後の節が矛盾しないかを読む**（表を足したら表の行の網羅も見る）
3. **Why not に書く事実が、いま直されつつあるものでないかを確かめる。** 一時的な事実は
   直った瞬間に嘘になるので、Why not の根拠にしない

## `subagent-control` — サブエージェントが指示どおりに動かなかった / 結果を取り逃した

| 起きたこと |
|---|
| プロンプトに「実装・ファイルの変更はしないこと」「ミューテーションは必ず元へ戻すこと」と明示したのに、実装検証のエージェントが実装を壊したまま次の実験へ進んだ |
| バックグラウンドで起動した計画レビューのエージェントの完了通知が届かず、結果を 1 度取り逃した |

**プロンプトで禁止しても守られない。** そのため対策を 2 段に置いてある。

1. エージェント定義（`.claude/agents/*.md`）に「返す前に `git status --porcelain` が空である
   ことを確認する」を書く
2. 呼び出し側は、**返答を読む前に `git status` を見て作業ツリーを戻す**
   （`implementation-flow`「サブエージェントの使い方」）

戻さずに指摘へ対応すると、自分の変更とエージェントの書き換えが混ざってコミットに載る。

## `hook-environment` — `.claude/hooks/` が発火しない環境だった

`echo hook-canary` が deny されずに通った回が 2 回。

**ゲートは git hooks（`harness/githooks/`）と CI にあるので、通ってしまっても手順は変わらない。**
その旨を PR 本文と記録に残す（実行環境ごとの統計が溜まる）。

`.claude/hooks/` の `pre-push-*` は同じスクリプトを走らせる**即時フィードバック層**であって、
強制力の層ではない（`.claude/hooks/README.md`「強制力の序列」）。

## セッションの URL を Issue に残す — 層を上げられない理由

規範は `AGENTS.md`「Issue に紐づいて起動したら、セッションの URL を Issue に残す」。層 3
（`session-url-notice.sh` / SessionStart）まで上げてある。**URL はセッションの中からしか
作れない**ので、規約だけに置くと「残そうと思ったが URL が分からない」で止まる。

- **Why not 層 2・層 1。** 見たいのは GitHub のコメントで、**リポジトリに痕跡が残らない**ため
  git hooks も CI も検査できない（`.claude/hooks/README.md`「カバー範囲と残る穴」の
  `block-npx.sh` と同じ型）
- **Why not フックから直接コメントを投げる。** 宛先の Issue 番号がフックからは確実に決められない
  （ブランチが `claude/issue-<N>-...` の形とは限らない）。間違えたコメントは消しても通知が残る

起点を「止まったとき」ではなく「着手したとき」に置いたのは、#135 が調査・分割・判断確定の
3 コメントすべてに URL を持たず、**調査を書いたセッションをあとから特定できなかった**ため
（トリガー起動のセッションは `list_sessions` の一覧にも載らない）。
