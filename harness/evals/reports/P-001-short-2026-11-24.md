# P-001-short　ディレクトリ例を命名規則1行に置き換えた結果

**短縮の採用は保留。** 通常課題の合格は現行版の1/2から短縮版の2/2に増えた。同名のモジュールを区別する課題では、両構成とも2回すべてでファイル名を `index.edge.test.ts` とした。短縮版が両方の課題で1回以上通るという事前条件に届かず、未使用の確認課題は実施しなかった。本番の規約には図を残す。[事前に登録した採用条件](https://github.com/DIO0550/design-composer/issues/1469#issuecomment-7133039737)

## 何を比べたか

A は現行のディレクトリ図6行、B は同じ位置に「テストファイル名は `{対象ドメイン名}.{カテゴリ}.test.ts` とする。」を置いた。課題を除く共通入力は A が770行、B が765行。前回は図を丸ごと削った。前回の実測記録は v1 で、同じ課題・規約は既定の v2 でも再現できる。今回は v3 の入力で A/B の両方を新しく測定した。[前回の P-001](P-001-2026-11-24.md)

| 課題 | 構成 | 1回目のファイル名 | 2回目のファイル名 | 全条件合格 |
| --- | --- | --- | --- | ---: |
| grid-step | A・図 | `GridStep.normal.test.ts` | `grid-step.normal.test.ts` | 1/2 |
| grid-step | B・1行 | `grid-step.normal.test.ts` | `grid-step.normal.test.ts` | 2/2 |
| label-limit | A・図 | `index.edge.test.ts` | `index.edge.test.ts` | 0/2 |
| label-limit | B・1行 | `index.edge.test.ts` | `index.edge.test.ts` | 0/2 |

8件すべてで対象モジュールの選択、入出力、境界値、既存スキャンが合格した。全条件の合格は A が1/4件、B が2/4件。不合格の5件では、ドメイン名を小文字の表記どおりファイル名の先頭に使う条件だけが落ちた。両課題を各2回試した範囲での観測である。

実行は2026年11月24日、Codex Work Mode の独立した8セッションで行った。継承するモデル設定は共通で、各セッションには1課題と片方の規約を渡した。1回目は課題順に AB・BA、2回目は BA・AB。正確なモデルビルド、時間、トークン、費用は未取得。

## 保存した回答から再採点する

[実験データ](P-001-short-2026-11-24.json) の `manifest` に基準コミット、置換前後の文、評価器、試行別の入力ハッシュを記録した。`answers` のキーは manifest と共通の試行 ID で、値には返されたパスと全入出力例、回答のハッシュ、採点結果が入っている。

リポジトリルートで次を実行すると、同じ入力を生成し、記録した8件を新しい出力先で採点し直せる。

```bash
cli=harness/evals/harness_eval.py
out=$(mktemp -d)/confirm
python3 "$cli" prepare --candidate P-001-short --repeat 2 \
  --base d199ad2483ca82c1a9d2b9134460d04a2d89105d --out "$out"
python3 - "$out" <<'PY'
import hashlib, json, sys
from pathlib import Path

out = Path(sys.argv[1])
record = json.loads(Path("harness/evals/reports/P-001-short-2026-11-24.json").read_text())
saved = record["manifest"]
fresh = json.loads((out / "manifest.json").read_text())
assert fresh["condition_fingerprint"] == saved["condition_fingerprint"]
for new, old in zip(fresh["trials"], saved["trials"], strict=True):
    assert all(new[key] == old[key] for key in ("task_id", "variant", "trial", "prompt_sha256"))
    sample = record["answers"][old["id"]]
    encoded = json.dumps(sample["answer"], ensure_ascii=False, sort_keys=True).encode()
    assert hashlib.sha256(encoded).hexdigest() == sample["answer_sha256"]
    envelope = {"prompt_sha256": new["prompt_sha256"], "answer": sample["answer"]}
    (out / "answers" / (new["id"] + ".json")).write_text(json.dumps(envelope))
PY
python3 "$cli" collect "$out" --agent 'Codex Work Mode（独立セッション）' --model 'GPT-6（ビルド未取得）'
```

未達の回答を含むので `collect` の期待する終了値は1。8件の採点を終えた時点で、A と B の成功件数、本表の試行別の合否が照合できる。
