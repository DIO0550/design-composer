# コーディング規約

実例（NG/OK・過去に踏んだ形）は [`harness/case-law/coding.md`](../harness/case-law/coding.md) を参照。

## コンパニオンオブジェクトパターン

ドメインロジックは**ドメインオブジェクト自身に閉じ込める**。
型と同名の `const` オブジェクトを定義し、生成・判定・変換ロジックをそこへ集約する。

## イミュータブル

**引数で受け取った値を変更しないことは全レイヤー共通の規約。** そのうえで `domains/` 内のファイルは可能な限り不変に保つ。

- 引数で受け取った配列・オブジェクトを破壊的に変更しない（`push` / `splice` / `sort` / プロパティへの再代入など）。走査中のカーソルやエラー蓄積用の配列も同様で、内部用の可変オブジェクトを引数で引き回さない
- 更新が必要な場合はコピーを作って新しい値を返す（スプレッド構文、`map` / `filter` / `toSorted` など）
- `let` による再代入も可能な限り避ける

## エラーと不在の表現（Result / Option）

**例外を投げない。** 失敗しうる処理は `Result<T, E>` を、値が不在になりうる処理は `Option<T>` を返す（`src/utils/Result.ts` / `src/utils/Option.ts`）。

- `throw` / `try-catch` は使わない。「見つからない」「不正な入力」「循環参照」などはすべて `Result.err` / `Option.none` で表す
- 戻り値の `T | undefined` / `T | null` を不在の表現に使わない。不在は `Option` で表す
- 在／不在・成否の**判定**は `Option.isSome` / `Result.isOk` を通す
- 失敗を握りつぶして既定値へフォールバックしない。呼び出し側が分岐できるようそのまま伝播させる（`Result.map` / `Result.flatMap` で連鎖する）
- **同じモジュール内で `throw` ベースと `Result` ベースを混在させない。** 公開 API の一部だけを `Result` 化して残りを `throw` のままにしない
- 例外に変換してよいのは、外部ライブラリの境界（`libs/`）と、失敗時にテストを落としたいテストコード（`Result.unwrap`）だけ

### 例外: Context のアクセサフック

`useContext` を包むアクセサフックが Provider の外で呼ばれた場合の `throw` は使ってよい。**既定値を返して埋めるのは禁止**（理由は判例 `over-guard`）。

## 関数のシグネチャ

- **引数は最大 3 つまで。** 4 つ以上になったら、常に一緒に渡る値をまとめた型を作って名前を付ける
- 引数が増える原因が「1 件ずつ受け取って呼び出し側でループしている」ことなら、**反復を関数の内側へ移す**（1 件ではなくまとまり全体を受け取る）
- 同じ型の位置引数が 2 つ以上並び、取り違えても型エラーにならない場合はオブジェクト引数にする
- **ジェネリクスを入れるのは「呼び出し側が型を決める」とき**に限る。選択肢を自分で列挙できるなら直和にする（型が似ていることは理由にならない）。呼び出し側が型を決めていないなら具体型で書き、用途が 2 つあるなら型を 2 つに分ける
- **閉じた union に束縛し、どれを入れるかを呼び出し側が決める**形は型引数でよい。判断基準は**実装が `T` の違いで振る舞いを変えていないか**であり、呼び出し件数では判断しない。`T` の中身を実行時に見て分岐したくなったら直和へ戻す（型レベルの導出は別 →「不正な状態を型で表現できなくする」）

## 値の語彙を型で閉じる

**取りうる値が仕様上決まっているものを `string` / `number` のままにしない。** union 型やテンプレートリテラル型で語彙を閉じ、タイポや単位違いをコンパイルエラーにする。

- 仕様（`docs/`）が列挙している語彙はそのまま union にする。定数から導出できる場合は `as const satisfies` で導出し、二重管理しない
- 単位付きの値は単位を型に含める。合成順が決まっている値は並びを型に表す
- ただし、プロパティごとに値域が違うなど**対で縛るコストが釣り合わない場合は無理に縛らず**、縛らなかった理由をコメントに残す
- **前提をコメントで書くのは、型で閉じたことにならない。** 「呼び出し側が保証する」と書いた時点で規律頼みになる。引数の説明が「〜であること」の形になったら、その条件を型にできないか先に考える
- **既存の型エイリアスへ付け替えるだけでは閉じられない。** 構造が `string` のままなら素の `string` が代入できてしまう
- 閉じたことの確認は**実際に弾かれるか**で行う。素の `string` を渡すコードを一時的に書いて `tsc` が落ちることを確かめ、`expectTypeOf` で固定する

### 値の集合から union を導出する

自前で値の集合を定義して union を作る場合は、**定数オブジェクト + `ValueOf`**（`src/types/ValueOf.ts`）で書く。値を名前で参照できるため、消費側が文字列リテラルを直接書かずに済む。走査が必要なときは `Object.values()` で配列にする。

- **定数オブジェクト名もプロパティ名も PascalCase にする**（`rules/naming.md`「定数は PascalCase」。ここでのキーは union の値の別名にあたるため）
- **union の型名は単数形、定数オブジェクトは複数形**にし、両方を同じファイルから export する
- スキーマなど**既存の定数から導出する**場合はこの限りではない（定義元の形に従う）

## 不正な状態を型で表現できなくする（型による境界）

**バグは直すのではなく、表現できなくする。** 型はコンパイラの装飾ではなく、不正な状態をコード上に存在させない防壁として設計する。実行時チェックやテストで「見つける」前に、そもそも書けなくすることを考える。

### 正しい状態だけを列挙する

boolean や `Option` の組み合わせで矛盾した状態が作れてしまうなら、**取りうる状態を直和（判別可能な union）で列挙**し、状態ごとに持つフィールドを変える。

### 列挙した状態の網羅を型で強制する

直和で列挙しても、**出し分け側が網羅していなければ意味がない**。`if` を並べると最後の枝がラベルのない受け皿になり、状態を 1 つ足したときに黙ってそこへ落ちる。

`switch` に `default` を置かずに書き、**戻り値の型に `undefined` を含めない**。case が抜けると「返さない経路がある」（TS2366）としてコンパイルエラーになる。

- **コンポーネントの戻り値は `ReactNode` ではなく `ReactElement` と書く。** `ReactNode` は `undefined` を含むため case が抜けても通ってしまう
- 文字列や数値を返す関数は、戻り値を素の `string` / `number` にすれば同じ効果が得られる
- `default` の追加・`never` への代入・状態をキーにした対応表は不要。**対応表は値が props 一式を受け取る関数になると呼び出しが読みにくくなる**ため、網羅のためだけに選ばない

### 生成時に検証し、不正な値を存在させない

制約を持つ値は、コンパニオンオブジェクトの `create` が**検証込みで生成**する（Smart Constructor）。検証に失敗しうるなら `Result` / `Option` を返し、「生成された = 制約を満たしている」を成立させる。生成後に呼び出し側が検証する設計にはしない（未検証の値が同じ型で流通してしまうため）。

### 処理の通過を型に刻む

「ある処理を通過したこと」（検証済み・解決済み・正規化済みなど）が後続処理の前提になる場合、その事実を**構造の違いを持つ型**で表し、未処理の値を処理済みとして渡せない**境界**を作る（Parse, don't validate: 検証は boolean を返すのではなく、検証済みを表す型への変換として書く）。

### ルール

- 消費側の関数は、自分が前提とする状態の型を**引数で要求する**（呼び出し側の規律ではなく型で誤用を防ぐ）
- **構造が変わらない型エイリアスの新設は禁止**（`type ResolvedProps = Props` 等）。構造的型付けでは何も防がないのに別の型があると誤読させる
- 状態の違いは可能な限り**実在する構造の違い**（必須キーの追加、値域の狭窄など）で表す。スキーマ等の定数から導出する場合は `as const satisfies` でリテラル型を保存し、型レベルで走査して導出する
- 狭い型への `as` は、**実行時にその事実を成立させる処理の戻り値 1 箇所のみ**許可する。境界以外での `as` によるすり抜けは禁止
- ブランド型は構造で表現できない場合の最終手段とし、防ぎたい誤用がコード上に現れてから導入する。**型定義は自前で書かず `src/types/Brand.ts` の `Brand<T, Tag>` を使う**（目印の `unique symbol` は使う側で宣言し、同じ制約の値を 1 つの型にまとめず、同じ制約の型が 2 つ以上あるなら互いに代入できないことを `expectTypeOf` で固定する）
- 型レベルの保証が仕様の一部であるときは、`expectTypeOf` のテストで退行を検知する

## ルール

- `domains/` に置くドメインオブジェクトは**型定義のみにしない**。生成・判定・変換ロジックを持つコンパニオンオブジェクトと必ずセットにし、**同一ファイル**で定義する（型だけを `type.ts` / `types.ts` に分離しない）
- ドメインの型はすべて `Readonly` / イミュータブルにする
- `features/` 層にドメイン知識（判定条件・計算規則など）を書かない。`features/` 層の責務は domains のオーケストレーションと UI に限る（ロジックの帰属は `rules/architecture.md` を参照）
- `class` は使用しない（type + コンパニオンオブジェクトで統一）
- ブロックのネストは **3 段まで**（lint の `max-depth` で強制）
- **同じ処理が 2 箇所に現れたら共通化する**（実装・テストとも）。汎用操作なら `utils/`、ドメインの規則ならコンパニオンオブジェクトへ置く
- 長い配列の結合をインラインのスプレッドで書かない。**中身に名前を付けた変数へ入れてから結合**し、何をどこから集めているかを名前で示す

## コメントは doc と Why / Why not に絞る

書いてよいのは **doc としての説明**（その関数・型・定数が何か、引数、戻り値、例外的な扱い）・**その形にした理由**（Why）・**採らなかった理由**（Why not）の 3 つだけとする。**それ以外は消す。** コメントは実装と一致させ、実装を変えたら同時に直す。`Why:` / `Why not:` のようなラベルを頭に置かず、理由の文だけを書く（書き方は判例 `消すコメントの見分け`）。

### doc に書く項目

**doc は「何をするか」を 1〜2 文で書く。** **挙動が及ぶ対象の列挙は概要ではなく仕様**なので、例示と混ぜて削らない（2 文を超えたときの見方・列挙と例示の見分けは判例 `doc の形`）。該当する項目だけを `@param`（引数が何を表すか）・`@returns`（何を返すか。不在・失敗を返すなら**どんなときにそうなるか**）・`@throws`（どんなときに投げるか）で書く。型の再掲は書かない。分割代入だけを引数に取る関数（props など）は `@param` を省いてよい。

### Why と Why not は別物として書く

**理由は原則書かない。型・テスト・lint が守っているもの、素直に書いた実装、自明な分岐はコメントへ写さない。** 書くのは**消したら次の読み手が同じ間違いをするもの**（型やテストで表現できず、外すと壊れるのに気づけない事情）に限る。書くときは、検討して捨てた案の Why not も 1〜2 行で添えて検討を一度で終わらせる。

- **理由の根拠に、いま直されつつある一時的な事実を置かない**（直った瞬間に嘘になるため）
- **理由は 1 つにつき 1〜2 行**に収める。3 行以上必要なら Issue に書くべき経緯が紛れ込んでいる
- 仕様・UI 案の引用（`docs/...`）は拠り所なので、理由の文に入っていても残す

## 外部の挙動は動かして確かめる

シェル・CLI・パーサ・外部フォーマット（JSON 等）の挙動を前提にしたコード（コミット手順・CI スクリプト・lint 設定を含む）は、**動くはずという想定だけで書かない。** 依存する挙動を小さく再現して確かめてから使う（確かめ方の実例は判例 `harness`）。

## 規約の適用範囲

**この規約は `src/` の TypeScript だけでなく、`.claude/hooks/` `.github/scripts/` などハーネス自身を実装するコード・doc にも及ぶ。**

- ブロックのネスト 3 段まで・条件式に名前を付ける、は対象言語（Python・シェル等）を問わず適用する
- 「同じ処理が 2 箇所に現れたら共通化する」は、コードだけでなく**同じ判断根拠を説明する doc・docstring・README の重複**にも適用し、片方だけ直せる状態を作らない

## 禁止事項

- `any` の使用
- `domains/` `services/` での I/O（console, fs, localStorage, fetch, Tauri API 等）— I/O は `libs/` のみ
