# 命名規約

実例（NG/OK・過去に踏んだ形）は [`harness/case-law/naming.md`](../harness/case-law/naming.md) を参照。

## 名前と実体を一致させる

**名前が約束することと、実際にやること・返すものを一致させる。** 名前を読んで想像した挙動と実装がずれていたら、名前が間違っている。

- **戻り値を名前に表す。** エラー配列を返すだけの関数を `validate*` と名付けない。集めて返すなら `collect*Errors` にする
- 探索していない関数に `find*` / `locate*` を使わない。その値を持つ新しい値を返すだけなら `with*` にする
- 公開 API も同じ基準で名付ける。「仕様書の語彙だから」を理由に、戻り値と食い違う名前を入口だけ残さない
- 1 つのモジュール内で語彙を混在させない（内部だけ直して公開 API を残すと混在が復活する）

## その名前が既に別の意味を持っていないか確認する

**新しく付ける識別子名は、書く前にこのリポジトリの他の場所を探す。** 命名規約に沿っていても、既存の接頭辞・UI 案・仕様書が既にその語を別の意味で使っていることがある。接頭辞・語幹を `grep` し、借りた慣習名がこの文脈で何を指すかを説明できるか確かめ、比喩・抽象語は UI 案・仕様書に何回出るかを数える（0 回ならこのリポジトリの語彙にない）。

## `And` を含む名前を作らない

`doAAndB` のような名前は、その関数が 2 つの振る舞いを持っている証拠。**名前を工夫して押し込めるのではなく処理を分ける。** 分けられないなら 2 つをまとめて表す 1 つの概念名を見つける（見つからないなら分けるべき処理）。

## 条件を組んだ式に名前を付ける

`&&` / `||` で 2 つ以上の条件を組んだ式を `if` や JSX にそのまま置かない。**何を判定しているかを表す名前の変数に入れてから使う。** 読み手は式を目で分解するまで、その分岐が何のためのものか分からない。

- **条件が 2 つ以上要る理由がコードから読み取れないなら、変数のそばにコメントを残す**
- 名前が付けられないのは、その分岐で何をしたいか決まっていないサインなので条件を組み直す
- 単独の条件（`isEmpty` / `list.length === 0` など）はそのまま置いてよい（名前を増やすことが目的ではない）

## 内容を表さない汎用語を使わない

`Entry` / `Info` / `Data` / `Detail` / `Manager` / `Helper` のような語は、何を指すのかを伝えない。ドメインの語彙で名付ける。

**名前が思いつかないのは、その型が 2 つの役割を抱き合わせているサイン**であることが多い。改名で解決しようとする前に役割を分けられないか確認する（分けた結果その型自体が不要になることもある）。

## 定数は PascalCase

**`const` の名前に SCREAMING_SNAKE_CASE を使わない。** オブジェクト・配列・スカラーの別や export の有無にかかわらず PascalCase で書く。**コンパニオンオブジェクトのメンバー**も値がオブジェクトであっても同じ（理由は判例）。

### 対応表のキーを PascalCase にするのは「キーが値の別名」のときだけ

データを引くための定数オブジェクトのキーは、**値が id や union の値そのもの**のときだけ PascalCase にする。値が表示文字列・オブジェクトなど**別のもの**なら、綴りが一致していても見出しなので元の表記を据え置く（表と判定の分かれ目は判例）。

## ファイル名

- **ファイル名を関数名にしない。** ファイルはモジュールであり中の 1 関数の名前ではない。分割するときはモジュールとして意味のある名前を付ける
- **React の API 名をモジュール名にしない。** 実装手段を指す名前は実装を差し替えると実態と食い違う。フックは**返すもの**で名付ける
- `src/domains/` `src/services/` `features/` のモジュールフォルダはケバブケース + `index.ts` とする

## メソッド名を既存のドメインに揃える

コンパニオンオブジェクトのメソッド名は既存のドメインオブジェクトの語彙に合わせ、同じ意味の操作に別の名前を与えない。

- **値を組み立てるのは `create`。** 引数から新しい値を作る入口はこれに揃える
- **別の表現から作り直すのは `from*`。** 変換元を名前に出す。`create` との使い分けは「引数がその値の材料か（`create`）、別の形で同じものを表しているか（`from*`）」
- **`of*` は使わない。** `create` / `from*` のどちらかに寄せる
- 判定は `is*` / `has*`、変換は `to*` / `*Value`、収集は `collect*` とする

## `utils/` のメソッドは動詞で始める

`src/utils/` の `<型名>Ex` は**組み込み型への操作**を集めた場所。メソッド名は**動詞、または結果そのものを表す語**で始め、`with*`（`withPrepended` のような形）にしない。

- **`with*` はドメイン側の語彙。** 「その値を持つ新しい値」を返すコンパニオンオブジェクトのメソッドに使う。`utils/` へ持ち込むと、同じ層の中で語形が 2 通りに割れる
- 条件付きの操作は条件を名前に出す。**結果の性質**で名付けると、その性質を保証していない実装と食い違う
