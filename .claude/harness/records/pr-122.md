## 指摘

### 1. 子の並びを出す条件を `hasChildren && isExpanded` のまま JSX に置いていた

- 分類: `naming`
- 出どころ: レビュー
- 内容: 行の組み立てを読む途中で条件 2 つの意味を追う必要があり、「三項演算子 +
  条件2つでわかりにくい」と指摘された。条件を `showsChildren` という変数へ出し、
  条件が 2 つ要る理由（子を持たない行は畳めないので `isExpanded` が常に true に
  なり、それだけでは空の `<ul>` が出る）をコメントで添えた
- 既存ルール: なし（rules/naming.md は名前と実体の一致・汎用語の禁止を扱うが、
  **式に名前を付ける**話は書かれていない）
- 次にどう防ぐか: **2 回目なのでルールへ追記する。** 1 回目は PR #113 の
  「ショートカットの一致判定を条件ごとに名前を付けて読めるようにする」
  （commit 8a36f38。3 つの一致条件を 1 本の式に並べていた）。同じ「複数の条件を
  1 本の式に組んだまま置いた」指摘なので、rules/naming.md に節を足す

### 2. 集合のトグルを新しいドメインオブジェクトとして作ろうとした（既存の同じ実装を見落とし）

- 分類: `utils-form`
- 出どころ: 自己修正（計画検証のサブエージェント）
- 内容: 「畳んでいる枝の名前」を持つ `CollapsedBranches` を
  `features/editor/domains/` に新設する計画だったが、`components/token-list` に
  まったく同じ Set のトグル（`toggled`）が既にあった。組み込み型に対する汎用操作
  なので `src/utils/SetEx.ts` に寄せ、`token-list` からも使う形へ計画を変えた
- 既存ルール: rules/architecture.md「utils の形式」（組み込み型に対する汎用操作は
  `<型名>Ex` に集約する／ドメインやサービスのローカル関数として書かない）、
  rules/coding.md「同じ処理が2箇所に現れたら共通化する」
- 次にどう防ぐか: 今回は記録のみ（1 回目）。ルールには書かれていて、
  **既存の実装を探す前に新設を決めた**のが原因。計画時に「同じ操作が既にどこかに
  無いか」を探す手順が implementation-flow のフェーズ 3 に無い

### 3. コンポーネント名が実体とずれていた（`TreeRow` / `SelectableRow`）

- 分類: `naming`
- 出どころ: 自己修正（実装検証のサブエージェント）
- 内容: `TreeRow` は名前が「1 行」だが、実体は「行 + 開いていれば配下のツリー全体」
  を返していた。また行の器を新設した結果、既存の `SelectableRow` は「行」ではなく
  「名前のボタン」になっていて、1 ファイル内で「行」が 2 つのものを指していた。
  `TreeBranch` / `SelectableName` へ改名した
- 既存ルール: rules/naming.md「名前と実体を一致させる」「1つのモジュール内で語彙を
  混在させない」
- 次にどう防ぐか: 今回は記録のみ（1 回目）。**既存の名前が指すものが変わった**の
  が原因で、新しく付けた名前ではなく既にある名前がずれた。ルールには書かれている

### 4. 開閉ボタンの当たり判定が 10px しか無かった

- 分類: `なし`
- 出どころ: 自己修正（実装検証のサブエージェント）
- 内容: 三角の列幅 10px は UI 案の実測値で、名前の左端を揃えるための値。それを
  そのままボタンの幅にしていたため、押す的が 10×14px 程度しか無かった。列幅は
  保ったまま、疑似要素で当たり判定だけを外へ広げた
- 既存ルール: なし（rules/ui-verification.md は UI 案への忠実さを扱うが、
  **操作できる大きさ**には触れていない。UI 案の `span` をボタンにするときのように、
  案に無い操作性を実装側で足す必要がある場面の指針が無い）
- 次にどう防ぐか: 今回は記録のみ（1 回目）。2 回目が出たら
  rules/ui-verification.md に「UI 案の飾りを操作要素にするときは当たり判定を別に
  考える」を足す

### 5. 同じ判定を 2 箇所で計算していた（`isSelected` / 子の有無）

- 分類: `なし`
- 出どころ: 自己修正（実装検証のサブエージェント）
- 内容: `isSelected` を行の器と名前のボタンの両方で計算し、「子を持つか」も三角の
  出し分けと `NodeList` の空チェックの 2 箇所で見ていた。器で 1 度だけ求めて渡す
  形へ直し、到達しなくなった空チェックは消した
- 既存ルール: rules/coding.md「同じ処理が2箇所に現れたら共通化する」（ただし
  分類の語彙に対応するタグが無い）
- 次にどう防ぐか: 今回は記録のみ（1 回目）

## 手戻り

**選択中の背景の塗り方を計画から変えた。** 計画では「押せる範囲と色の付く範囲を
一致させる」ために名前のボタンだけを塗るとしていたが、UI 案の実マークアップを
計画検証で読み直したところ、選択行の背景は字下げと三角を含む**行全体**に掛かって
いた。三角の列を足したうえで従来の塗り方を続けると背景が今より狭くなり、
UI 案へ寄せる issue で逆行するため、器へ移した。

外れた時点で #112 のコメントへ追記済み。
