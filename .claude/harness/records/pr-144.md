ゴールは「UI 案（docs/Design Composer.html）の `Layers` パネルどおり、artboard の一覧を
上段の `Artboards` に出し、ツリーは選んだ 1 枚の中身だけを出す。artboard のアイコンは
`#`」。達成した。

人によるレビュー指摘は 0 件、CI の失敗も 0 件。以下はすべて実装検証のサブエージェント
から出たもの（計画と計画検証は前のセッションで済んでいたため、この回は実装から入った）。

ずれが 1 点ある。**「今見ている artboard を保持せず導出する」という計画どおりの実装が、

していた規則なので独断で変えず、#112 に案を添えて起こしたうえでこの PR はそのまま出した。

## 指摘

### 1. 選択が外れる操作が「見ている artboard の切り替え」になっていた

- 分類: `plan`
- 出どころ: 自己修正（実装検証のサブエージェント）
- 内容: `currentArtboard` を「選択 → 載っている artboard / 選択なし → 先頭」で導出した
  ため、`selectedName` が `none` になる操作がそのまま表示の切り替えになる。プロパティ
  パネルの「選択を解除」1 クリック、ノードの削除、その直後の undo の 3 経路で、
  見ている artboard が 1 枚目へ飛ぶ。変更前は全 artboard がツリーに出ていたので
  この飛びは存在せず、**この PR で入った振る舞いの後退**
- 既存ルール: なし。`rules/coding.md`「不正な状態を型で表現できなくする」は
  「持たずに導出する」を後押しするが、**導出の入力が失われたときに何が起きるか**は
  扱っていない。`plan-review.md` の観点にも無い
- 次にどう防ぐか: **4 回目なので観点へ追記する。** 「状態として持たず導出する」と
  決めた計画では、**導出の入力が失われる操作を数える**を `plan-review.md` に足す。
  今回の修正自体は #112 で判断を仰いでから別 PR で行う

### 2. 既定値のおかげで壊しても通るテストを 2 件書いた

- 分類: `test-behavior`
- 出どころ: 自己修正（実装検証のサブエージェント）
- 内容: 「ノードを選ぶとそれを載せている artboard になる」を確かめる 2 件
  （`editor-state.current-artboard` の孫ノード、`artboard-list.normal` の配下ノード）で、
  **先頭の artboard 配下のノード**を選んでいた。`findOwningArtboard` がノードに対して
  常に `none` を返すよう壊しても、「選択なしは先頭」の既定で同じ答えになり通ってしまう。
  fixture を 2 枚目へ移して、壊すと落ちることをミューテーションで確認した
- 既存ルール: `rules/testing.md`「assert は『落ちうるか』と『1 つの仕様か』で見る」
  （PR #124 で足したもの。**書いてあるのに踏んだ**）
- 次にどう防ぐか: **5 回目。** ルールはあるが、今回の踏み方には共通の形がある
  ——「既定値・fallback があるので、規則を壊しても同じ答えになる入力を選んでいた」。
  この一段具体を `rules/testing.md` の同じ節に足す

### 3. `ArrayEx.first` があるのに `artboards[0]` を直書きした

- 分類: `utils-form`
- 出どころ: 自己修正（実装検証のサブエージェント）
- 内容: `Option.fromNullable(document.artboards[0])` と書いたが、`src/utils/ArrayEx.ts`
  の `first` が中身までまったく同じだった。同じ feature の `edit-history` は

- 既存ルール: `rules/architecture.md`「utils の形式」（組み込み型に対する汎用操作は
  `<型名>Ex` に集約する）
- 次にどう防ぐか: **2 回目なので観点へ追記する。** 1 回目は PR #122 の指摘 2
  （`SetEx.toggle` に当たるものが `token-list` に既にあった）で、そのときの記録が
  「計画時に『同じ操作が既にどこかに無いか』を探す手順が implementation-flow の
  フェーズ 3 に無い」と書いている。**同じ原因で 2 回目**なので `plan-review.md` に足す

### 7. `aria-current` が同じペインの中で 2 つの意味を持つ
