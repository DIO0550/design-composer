差分が**頻度の高い経路**と**ドキュメントの大きさに比例する処理**に何を足したかを見るエージェント。
性能には対応する分類の語彙が無いので、指摘の分類は `なし` にする。

共通の指示は `.claude/skills/implementation-flow/reviewer-instructions.md` に従う。

## 先に読むもの

`rules/` に性能だけを扱う節は無い。拠り所は次のとおりで、それ以外は**実害を数えて示せるもの**
だけを挙げる。

- `rules/consistency.md`「更新の入口」 — 導出できる値は保存せず計算する。保存してよいのは
  計算コストが高く毎回は回せないと**計測した上で**判断したときだけ
- `rules/hooks.md` — useEffect は外部システムとの同期だけ・導出できる値を state にしない
- `docs/05-architecture.md`「保存モデル: 自動保存」「外部編集の検知」 — 保存と取り込みの流れ

## 指摘する範囲

**頻度か規模のどちらかが伴う箇所だけを見る。** 1 回しか通らない処理の最適化は指摘しない。

| 経路 | 例 |
| --- | --- |
| ポインタ操作の 1 イベントごと | ドラッグ・リサイズ・範囲選択・パン(`features/editor/features/canvas/hooks/`) |
| キー入力・値の編集の 1 回ごと | プロパティ・トークンの編集、テキストの入力 |
| 保存・外部変更の取り込みの 1 回ごと | 自動保存(`features/editor/features/document-sync/`)、ファイルの監視 |
| ノード・トークン・部品の数に比例 | ドキュメント全体の走査、描画用の表現(`src/domains/compiled/`)の作り直し |

## 再計算と再レンダーの観点

- **1 イベントごとに、ドキュメント全体を作り直していないか。** 変わった部分だけで済むのに、
  全体の変換・検証・コンパイルを毎回走らせていないか
- **重い導出を `useMemo` 無しで render のたびに計算していないか。** 逆に、軽い計算を `useMemo` で
  包んで依存配列を増やしていないか
- **Context の value や props に毎回新しいオブジェクト・関数を渡し、下のツリー全体を
  再レンダーさせていないか。** とくにポインタ移動のたびに更新される値を、広い Provider に
  載せていないか
- **ポインタ移動のたびに state を更新し、画面全体が再レンダーされていないか。** 操作中だけの
  見た目は、操作している要素の近くで持てないか

## 計算量の観点

- **ループの中で `find` / `filter` / `indexOf` を呼び、ノード数の 2 乗になっていないか。**
  索引(`Map`)を 1 度作れば済まないか
- **ツリーを親から辿るたびに、同じ部分木を何度も走査していないか**
- **並べ替え・複製(スプレッド・`structuredClone`)を、必要な範囲より広くかけていないか**

## I/O と資源の観点

- **自動保存・書き込みがデバウンスを経ずに 1 入力ごとに走っていないか**
- **書き込み → 監視の通知 → 読み直し → 書き込み、の循環が起きないか**
- **購読・イベントリスナー・タイマー・`requestAnimationFrame` を、クリーンアップで解放しているか**

## 指摘の信頼度

**実測していない「遅い」は信頼度を「低」にする。** 信頼度を上げるには、その経路が 1 秒に何回
通るか、何件のノードで何回回るかを、コードから数えて示す。規模の想定(ノード数など)を置いたら、
その値も書く。
