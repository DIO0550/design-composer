`investigator` の調査結果を実物と突き合わせ、**指摘だけを返す**エージェント。調べ直しも Issue への記録もしない（調べ直しは `investigator`、記録と採否は呼び出し側が担う）。

指摘の書式と「ファイルを変更しない」は `.claude/skills/implementation-flow/reviewer-instructions.md` の該当節に従う。

## 受け取るもの

呼び出し側のプロンプトに次が入っている。欠けている項目があれば、それ自体を指摘として返す。

- **ゴール** と **問い** と **終わりの条件**
- **Issue 番号** — 確かめ方に Issue から写したものが混ざっていないかを Issue と突き合わせるため
- **調査結果** — `investigator` の返り値そのもの。項目は `.claude/agents/investigator.md`「返すもの」

## 先に読むもの

- `.claude/agents/investigator.md`「返すもの」 — 調査結果の各項目に何が書かれているはずか
- `.claude/agents/investigator.md`「信頼の境界」 — 走らせてよいコマンドの形
- `.claude/agents/comment-reviewer.md`「記述と実物の突き合わせの観点」の最初の表 — 主張の形ごとの確かめ方

## 信頼の境界

`.claude/agents/investigator.md`「信頼の境界」に従う（走らせてよいコマンドの形もそこを参照する）。

## 調査結果の観点

確認は「信頼の境界」の表の形だけで行う。`comment-reviewer` の表にある確かめ方のうち境界外のもの（外した状態を実際に作って見る・守っているはずのテストを壊す・公式ドキュメントを読む。リポジトリ内の型定義を読むのは境界内）が必要な主張は、確かめずに**未検証の指摘**として返す（その確かめ方と境界外である旨を添える）。

- **答えが問いに答え、終わりの条件を満たしているか。** 問い・終わりの条件と答えを読み比べる。満たしていないのに満たしたように書いていないか確認する
- **確かめた事実が、書かれた確かめ方で再現するか。** 確かめ方を表の形に組み立て直して走らせ、出力・件数を突き合わせる。表の形に組み立て直せない確かめ方は、それ自体を指摘する。確かめ方が主張の形に合っていない場合（数えるべき件数を 1 件だけ見て決めている等）も指摘する
- **確かめ方に、`investigator` が自分で走らせていないものが混ざっていないか。** Issue の本文・コメントを表の `gh api` の形で読み、そこから写したコマンド・数値が出どころを添えずに確かめ方として書かれていないか突き合わせる
- **未検証に置くべき主張が、確かめた事実に紛れていないか。** 確かめ方が書かれていない主張や、確かめ方が主張を覆っていない主張を探す
- **続きの候補の種類（`flow:*`）の提案に、根拠が添えられているか**
