# `flow:refactor`: 振る舞いを変えず、既存のテストで確かめる

`flow:refactor` の Issue で、`SKILL.md` の各フェーズに**足す**手順。書いていないフェーズは
`SKILL.md` のまま。

**振る舞いが変わっていない根拠は、書き換えていない既存のテストだけ。** テストを実装と一緒に
書き換えると、緑のままでも振る舞いが変わっていないとは言えなくなる。

## 守る範囲

次のファイルを**守る範囲**、その下の配線を**テストを走らせる配線**と呼ぶ。

| 守る範囲 | 中身 |
| --- | --- |
| `__tests__/` | vitest のテストとその共有物(フィクスチャ・ヘルパー) |
| `*_test.rs` / `test_support.rs` | Rust のテストとその共有物(`src-tauri/`) |
| `*-cases.sh` / `cases-fixtures.sh` / `cases-report.sh` | 検出器・スクリプトの判定表とその共有物 |
| `src/test-setup.ts` | vitest のセットアップ |
| `*.stories.tsx` / `__stories__/` | VRT が撮るストーリーとその共有物 |

テストを走らせる配線は、`src-tauri/` の `mod *_test;` / `mod test_support;`、`.github/workflows/` の
`-cases.sh` を走らせる `run:`、`vite.config.ts` の `setupFiles`。消すと、テストを書き換えずに
走らなくできる。

守る範囲の中で変えてよいのは次だけ。

- **assert を含むテストの本文は変えない。** 期待値・入力・テストの名前を含む
- **参照先(import のパス・`mod` の位置)の書き換えは、計画の移動表にある移動先へだけ。**
  同じものを指したまま場所が変わる書き換えに限り、別の実装・スタブへの向け替えはしない
- **公開 API の改名は、計画の名前の対応表(旧名 → 新名)にある分だけ。** 表に無い名前を変えると、
  `parse` → `parseLoose` のような向け替えが改名に紛れて読めなくなる
- テストを足すのはよい。**消さない**(skip を含む)

## フェーズ 3: 計画に足すもの

- **守っている既存テスト。** 触るコードを守っているテストのファイルと、走らせるコマンドと件数
- **現状を固定するテスト。** 守っている既存テストが無い範囲には、今のコードで通るテストを
  先に足す計画にする
- **移動表**(ファイル・モジュールの移動元 → 移動先)と**名前の対応表**(旧名 → 新名)。
  無いなら「無し」と書く
- 仕様の変更や既存テストの書き換えが要ると分かったら、`flow:refactor` に合わない作業なので
  計画せずに止め、`SKILL.md` フェーズ 1「種類の確定」の 6 に従う

## フェーズ 5: `implementer` を 2 回に分ける

渡すものの `回:` で分ける(`SKILL.md` フェーズ 5 の渡すもの)。

1. **1 回目: 現状を固定するテストだけを足させる。** 今のコードのまま通ることを返させる。
   `git status --porcelain` に出るのは計画の現状を固定するテストだけ(`SKILL.md`
   「サブエージェントの使い方」の突き合わせを、この範囲に狭める)。commit したものが
   **1 回目のコミット**で、比較の基準になる
2. **2 回目: リファクタさせる。** commit したら、親が次の 2 つの出力を読む

   ```bash
   git diff <1 回目のコミット> HEAD -- ':(glob)**/__tests__/**' ':(glob)**/*_test.rs' ':(glob)**/test_support.rs' ':(glob)**/*-cases.sh' ':(glob)**/cases-fixtures.sh' ':(glob)**/cases-report.sh' src/test-setup.ts ':(glob)**/*.stories.tsx' ':(glob)**/__stories__/**'
   git diff -U0 <1 回目のコミット> HEAD -- src-tauri .github/workflows vite.config.ts | grep -E '^-.*(mod [a-z0-9_]+_test;|mod test_support;|-cases\.sh|setupFiles)'
   ```

   - 1 行目は守る範囲の差分。出てよいのは、足したテストと、移動表・名前の対応表にある書き換えだけ
   - 2 行目はテストを走らせる配線から消えた行。出たら、移動表にある移動の片割れかを確かめる
   - 外れていたら、外れた行を指摘として `implementer` に戻す

この 2 行は読む作業を減らさない。import の書き換えを取り除いてから比べる検査は #1406 で
判定表つきのスクリプトにする(判定表を持たないコードをこの文書に埋めない)。

## フェーズ 6: 直しでも既存テストを変えない

- 採用した指摘を直すときも、守る範囲の決まりは同じ。テストが足りないという指摘には、
  既存テストを書き換えず新しいテストを足して応える
- 直しのたびに、フェーズ 5 の 2 行を読み直す
- **`test-reviewer` はそのまま呼ぶ。** 振る舞いが変わっていない根拠は既存テストだけなので、
  それが実装を守っているかを実測する役が要る

## フェーズ 7: VRT の差分を承認しない

- **`Storybook Visual Regression` の差分は `visual-approved` で通さない。** 振る舞いを変えない
  変更で見た目が変わったなら、それは直す対象(`rules/ui-verification.md`「Storybook の視覚差分(VRT)」)
- **story の `title` と export 名を変えない。** 変えると story の id が変わり、VRT は差分ではなく
  new と deleted の組として出す。new は落ちないので、見た目がずれても緑のまま通る
  (`harness/case-law/process.md`「`vrt-blind-spot`」)。変えるなら計画で id が変わることを予告し、
  1 回目のコミットと HEAD をそれぞれ playwright-cli で撮って目視で比べる
  (`rules/ui-verification.md`「表示確認」)
- **story の `args` を変えない。** 写る中身が変わり、差分が出ても出なくても比べたことにならない
