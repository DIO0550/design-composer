# 検証の周回

`implementation-flow` のフェーズ 4 とフェーズ 6 の第 1 段で使う。**上限はフェーズごとに初回を含めて 3 周。** 前提を確かめ直す合図が先に出れば、上限を待たずに抜ける。

## 各周の進め方

1. 初回の検証範囲は各フェーズの手順に従う。2 周目以降は、**前周で採用した指摘を出した観点と、そのために直した差分だけ**を見る。再検証で指定する観点は「指摘元のエージェント名と、定義にある個別の観点名」の組で照合する。呼ぶ条件の表の大分類や指摘の分類タグでは代用しない。周辺は影響を確かめるために参照できるが、全体の再レビューはしない
2. 依頼したすべての観点から、根拠のある検証結果を受け取る。前周の採用指摘が未解消なら、同じ観点の指摘として今回も掲げ、採否を決め直す。修正に起因する依頼範囲内の新しい指摘も採否を決める。範囲外の発見は別記し、この周の採用件数にも次の再検証範囲にも含めない
3. 下の表で行き先を決め、各周の採否と理由を Issue に記録してから移る。採用を取り消して修正しない場合はその理由を記録し、採否を決めた周で行き先を再判定する

## 担当外の回帰が見つかったとき

修正差分が守るべき振る舞いや制約を壊す具体的な根拠があるなら、親はその回帰を別記し、続行してよいかとその根拠を Issue に残す。判断に不足があれば、担当のエージェントにその懸念だけを該当する修正差分で確認させる。この確認は周回の採否や再検証範囲に入れない。

判断がつかない間は同じ周で保留する。修正による回帰が確認され、未解消なら、局所修正の周回に足さず下の表に従って計画へ戻す。回帰でないか今回の修正に起因しないと判断した場合は、理由と必要な申し送りを残して続ける。

## 収束と打ち切り

上から順に判定する。

| 状態 | 行き先 |
| --- | --- |
| [前提を確かめ直す合図](https://github.com/DIO0550/design-composer/issues/1483) が出た | 上限を待たず、前提の再確認へ |
| 結果が未確定（未返却・検証失敗・再検証に必要な修正差分なし・判断保留。担当外の回帰の判断待ちも含む） | 「指摘なし」にはせず、同じ周の不足を補うか判断を待つ。3 周目も同じ |
| 3 周目の結果と採否が確定し、採用した指摘が残った | 前提の再確認へ。4 周目も、未検証の修正を入れて次の手順へ進むこともしない |
| ゴールや種類の変更が必要と決まった、またはフェーズ 6 で方式の置き換えを採用した | 局所修正はせず、各フェーズの手順にある戻り先へ |
| 修正に起因する担当外の回帰が確認され、未解消 | 採用件数が 0 件でも次へ進まず、フェーズ 3 へ戻る |
| 結果と採否が確定し、再掲した指摘を含めて採用が 0 件 | 収束。各フェーズの次の手順へ |
| 上限前に採用した指摘が残った | 採用分を直し、次の周で確かめる |

フェーズ 4 でゴールや種類を変えずに計画上の方式だけを直す場合は、通常の再検証に含める。

合図は各周の開始前と、採否の決定や差し戻しの後に確認する。#1483 の手順が導入済みなら、そこに定める合図と発火時点を優先する。

未導入時は、同じ未解消の指摘をこのフェーズ内で `planner` / `implementer` に 2 回差し戻した時点を合図とする。対象と原因を追える識別子で指摘を照合し、同じ観点でも解消済みの指摘とは別の新しい指摘なら初回として数える。計画 v3 は版番号だけでは合図にしない。第 3 周に進む場合は、開始前に版番号で止めず、結果と採否が確定してから上限を判定する。

未導入のため再確認へ移れないときは、移る理由（合図または上限）と確かめ直す前提、未解決の指摘を Issue に書いて判断を待つ。収束扱いでは先へ進まない。

## Issue に残す記録

[検証の採否の書式](https://github.com/DIO0550/design-composer/issues/1481) に合わせ、周ごとに 1 件残す。見出しのフェーズ番号を置き換え、周回番号は見出しに足さない。

```markdown
## 検証の採否（フェーズ 4）
セッション: <URL>

第 <N> 周 / 対象: <計画の版または実装のコミット>
再検証の範囲: <直す前後の版またはコミットと、対象観点>

| 観点 | 指摘 | 採否 | 理由 |
| --- | --- | --- | --- |
| <観点> | <指摘または無し> | <採用・不採用・保留・対象外> | <判断の根拠> |

採用: <件数> 件
次: <次の周・次の手順・前提の再確認・判断待ち>
```

初回の範囲には計画全体または PR 全体の差分と書く。フェーズ 6 では見出しを `## 検証の採否（フェーズ 6）` にする。採用が 0 件の周も省かず、前周の採用分がある場合は解消を確認した根拠または採否を見直した理由を添える。指摘欄には対象と原因を追える識別子を記し、未解消の指摘を再掲したときは同じ識別子を使う。
