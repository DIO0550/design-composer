# `flow:bugfix`: 再現を先に固定してから直す

`flow:bugfix` の Issue で、`SKILL.md` の各フェーズに**足す**手順。書いていないフェーズは
`SKILL.md` のまま。

**修正より先に、症状を再現して落ちるテストを書いてコミットする。** 修正と同時に書いたテストは、
修正前のコードで落ちたかが誰にも分からない。直したつもりで別の箇所を直していても通る。

## フェーズ 1: ゴールに症状を書く

ゴールに加えて、**症状を 3 つに分けて** Issue に書く。

- 再現手順(どの入力・操作・状態から)
- 期待する結果(拠り所の `docs/` の節があれば添える)
- 実際の結果

再現手順が書けないなら、ゴールが決まっていない(`SKILL.md` フェーズ 1 のとおり止める)。

## フェーズ 3: 計画の先頭に再現テスト

テストケースの一覧の**先頭**に再現テストを置き、次を書く。

- 置くファイルと、テストの名前(仕様の文。`rules/testing.md`)
- 修正前のコードで、**どの assert がどの値で落ちるか**(期待した値と、実際に出る値)
- **今ある公開 API だけで書く。** 修正で足す API を使うと、修正前は型エラーで落ちて assert まで
  届かない
- **2 回目(修正)で書き換える既存テストと同じファイルに置かない。** 同じファイルだと、
  フェーズ 5 の `git diff --exit-code` が再現テストの書き換えと既存テストの書き換えを見分けられない
- **自動テストで再現できないなら、その理由と代わりの確かめ方**(playwright-cli で撮る等)を書く

## フェーズ 5: `implementer` を 2 回に分ける

`implementer` は commit しないので、1 回で書かせると「再現テストが先に落ちたコミット」が作れない。
渡すものの `回:` で分ける(`SKILL.md` フェーズ 5 の渡すもの)。

1. **1 回目: 再現テストだけを書かせる。** 修正はさせない
   - `git status --porcelain` に出るのは計画の再現テストのファイルだけ(`SKILL.md`
     「サブエージェントの使い方」の突き合わせを、この範囲に狭める)
   - 返ってきた `pnpm run test:run` の出力で、**落ちたのが再現テストだけで、落ち方が計画に書いた
     assert の失敗である**ことを親が確かめる。型エラー・import の失敗・他のテストの失敗は
     再現になっていないので、計画へ戻す
   - 確かめたら commit する。このコミットが**再現テストのコミット**
2. **2 回目: 修正させる。** 再現テストは書き換えさせない
   - 返ってきたら、親が次を走らせて終了コードが 0(再現テストのファイルに変更が無い)ことを確かめる

     ```bash
     git diff --exit-code <再現テストのコミット> -- <再現テストのファイル>
     ```

   - 同じ再現テストが通っていることを、返ってきた `pnpm run test:run` の結果で確かめる

## フェーズ 6: 直しのたびに同じコマンド

採用した指摘を `implementer` に直させたら、そのたびにフェーズ 5 の `git diff --exit-code` を
走らせ直す。直しでも再現テストは書き換えさせない。

## フェーズ 7: PR 本文に 2 つのコミット

PR 本文に、**再現テストのコミット**と**修正のコミット**を並べて書く。読む人が前者だけを
チェックアウトして、テストが落ちることを確かめられるようにする。
