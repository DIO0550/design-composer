# 計画の実行可能性を確かめる

計画の**妥当性**（帰属先は正しいか、却下案の理由は理由になっているか）はフェーズ 4 の
サブエージェントが見る。ここで見るのは**実行可能性**だけ — 書いたとおりに手を動かしたとき、
型が通らない／テストが書けない／数え漏らしたファイルが出てこないか。

**判断ではなく段取り。** 下の 3 つを**この順で**実行する。順番を入れ替えると意味が変わる
(呼び出し側を数える前にテストを書き始めると、後から型が通らなくなって書き直しになる)。

由来: `plan` 分類が観点層（`plan-review.md`）へ介入後も再発し続けたため、観点から
スキルへ層を上げたもの（`harness/records/pr-185.md`）。**観点は書かれていたが、
計画を書く側が実行していなかった** — 実行する手順として切り出すのが目的。

---

## Step 1: 触る公開 API の呼び出し側を数える

計画で**型・props・公開メソッド・定数の名前や形を変える**なら、それを使っている側を
1 つ残らず挙げる。

```bash
# 変える名前ごとに実行し、出たパスをすべて計画のファイル表と突き合わせる
grep -rn "<変える名前>" src/
```

- **`src/` 全体にかける。** 「この feature の中だけだろう」で範囲を絞らない
  (PR #185 は `DocumentErrorList` を編集画面の部品だと思い込み、**開始画面
  `DocumentStart` が同じ部品を使っている**ことを数え漏らして、props の直和が型で
  通らない計画になった)
- 出たパスは **`*.stories.tsx` と `__tests__/` も数える**。実装ファイルだけ直しても
  typecheck が落ちる
- 名前を変えずに**枝を足すだけ**の場合も数える。こちらは typecheck も lint も落ちないので、
  数え漏らしても誰も教えてくれない(アクションの直和・状態の直和が該当)

**突き合わせた結果を計画のファイル表へ反映してから次へ進む。** 「grep したが表は直して
いない」は数えたことにならない。

## Step 2: 計画に書いたテストが、今の足場で書けるかを確かめる

計画のテストケース一覧を上から読み、**それぞれについて「今あるもので書けるか」**を確かめる。

| 確かめること | 見る場所 |
| --- | --- |
| その状態に到達する手段が既にあるか | 対象の `__tests__/setup.tsx`、`features/<x>/__tests__/` |
| 代役（フェイク）に必要な口があるか | `src/libs/*/fake/` |
| 既存のヘルパーが**その観点に使えるか** | ヘルパーの中身を実際に開いて読む |

**ヘルパーは名前ではなく中身で判断する。** PR #185 は通しテストで既存の
`breakFileExternally` を使う前提で計画したが、中身が `"{ 壊れた"` を書くもので、
字句スキャンで落ちるため確かめたい行（ノードを指すエラー）が 1 つも出なかった。
同じ回に「`save` が失敗するフェイク」も計画に書いたが、代役に失敗注入の口が無かった。

**足りないものが見つかったら、それも計画のファイル表へ足す。** テストの足場は
「実装のついで」ではなく計画の一部。

## Step 3: 消すものの行き先を数える

計画に「消す」「置き換える」が含まれるなら、次の 3 つを数える。**どれも typecheck でも
lint でも落ちない。**

| 見るもの | 探し方 |
| --- | --- |
| 呼び出し元が 0 になる props / メソッド | `grep -rn "\.<名前>\b" src/` で残りの参照を数える |
| 消したものに言及しているコメント・doc | `grep -rn "<消す名前>" src/` を全体にかける |
| 戻り値の未使用プロパティ | フックが返す値それぞれに**消費側があるか**を 1 つずつ確かめる |

3 つ目は PR #185 で実際に出た（`isReverting` を返す計画だったが受け口が無く、
誰も読まない戻り値になるところだった）。**「返す」と書いたら「誰が読むか」を書く。**

---

## 通したことの記録

3 つを通したら、計画の Issue コメントに数えた結果を残す。

```markdown
### 実行可能性の確認

- 触る公開 API: `DocumentErrorList` の props → 呼び出し側 7 ファイル（`grep -rn` で確認）。
  うち `document-start/index.tsx` は計画に挙げていなかったので追加した
- テストの足場: `breakFileExternally` は字句エラーを書くので Reveal の行が出ない →
  スキーマ検証で落ちるヘルパーを新設（ファイル表へ追加）
- 消すもの: 無し
```

**「確認した」だけでは書いたことにならない。** 何を grep して何件出たか、計画をどう直したかを
書く。直しが 0 件だったなら「差分なし」と書く。

---

## このスキルを飛ばしてよい場合

- 公開 API・props・型の**形を変えない**（中身の実装だけを直す）
- テストを 1 件も足さない
- 消すものが無い

3 つすべてに当てはまるときだけ飛ばしてよい。飛ばしたなら、飛ばした理由を Issue に 1 行書く
（`implementation-flow` の「フェーズを飛ばさない。飛ばすと決めたなら理由を Issue に書く」）。
