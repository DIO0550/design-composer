# 06. UI・キャンバス操作

GUI 編集のスコープを規定する。編集の実体はすべて「ドキュメント（JSON）への変更」であり、GUI は core に対するクライアントの1つである（AI・外部エディタと対等）。

## 画面構成

Figma 型の3ペイン。

| ペイン | 内容 |
|---|---|
| 左 | ツリービュー（データモデルの木をそのまま表示）＋部品一覧 |
| 中央 | キャンバス。artboard はそれぞれのキャンバス座標に置く（座標を持たないものだけ配列順に自動配置）。ズーム / パンは非永続の view state |
| 右 | プロパティパネル。スキーマから自動生成（03-schema）。`enabledWhen` により表示を出し分ける |

- アプリ内 JSON ビューは**持たない**。JSON を見たい場合は外部エディタに委ねる（自動保存によりファイルは常に最新）
- この表が規定するのは**ドキュメントを開いている間**の画面

### 開く前の画面（開始画面）

ドキュメントを開いていない間は、3 ペインの代わりに開始画面を出す。持つのはアプリ名・`開く` / `新規作成`・最近使ったファイルの一覧・ファイルを落として開ける旨の案内・開けなかった理由・メニューやドロップからの操作を受け取れないときのその旨。

- **最近使ったファイルは、ファイル名と収めているフォルダの名前で並べる。** 同名のファイルを別フォルダで開いたときに区別できるようにするため。1 件も無ければ枠ごと出さない
- **どこに残すかは規定しない**（アプリ自身の状態の置き場は 05-architecture の通り未規定）

### 開く / 新規作成の導線

ドキュメントを開いている間は、開始画面が消えるので **OS のメニュー**（⌘O / ⌘N）とウィンドウへのファイルのドロップが導線になる。上端のバーには置かない。

## 選択

- キャンバス上のクリックとツリービューの選択は双方向に連動する
- 選択状態は非永続（実行時のみ）。外部編集によるリロード後の選択復元は name によるベストエフォート
- 選択は「なし」「1 つ」「複数」の 3 つの状態を取る
- **Esc で選択を「なし」へ戻す**（下記「編集操作の一覧」）。artboard を選び直したときも前のノードの選択は外れる

### 複数選択

複数を選ぶ手段は `Select all N instances`（インスペクタの `Instance` 節）だけで、**同じ部品を指すインスタンスをまとめて選ぶ**用途に限る。任意のノードを選び足す操作は持たない。

- **N の数え方**: artboard の配下にあり選択できるインスタンスの数。部品定義の中にある参照ノードはキャンバスに描かれても選択の対象にならないため数えない。`Assets` の一覧が出す使用数（`×N`）は部品定義の中の参照も数えるので、**2 つの数は食い違うことがある**
- そのインスタンスしか無い（N が 1 以下の）ときはボタンを押せない（押しても選択が変わらないため）
- **編集操作は複数選択中は行えない**。削除・コピー・並べ替え・props 編集・リサイズ・部品化・インスタンスの解除・挿入はいずれも 1 つだけ選んでいるときの操作とする
- **インスペクタ**: 帯に選択数を出し、本文には編集欄を出さない（選択の解除だけを残す）
- **キャンバス**: 選んだものすべてに選択の枠を出す。リサイズハンドルは 1 つだけ選んでいるときに出す
- **ツリービュー**: 映すのは 1 枚の artboard の中身なので、選択が artboard をまたぐときは**今見ている artboard のぶんだけ**が選択表示になる。今見ている artboard は選択の先頭が載っている 1 枚
- **Assets**: まとめて選んでいる間も、出どころの部品の行は `source of selection` として強調したままにする

## キャンバス直接操作

Figma 寄りの直接操作を採用する。

- **移動（ドラッグ）**: 運んでいるノード自身の `placement` で意味が変わる。
  - `flow`（既定）のノードは**ツリー内の移動**として解釈する（02-data-model）。ドロップ先は「どの Box の何番目の子になるか」をハイライトで提示する
  - `absolute` のノードは**その親の中の座標の変更**として解釈する。掴んだノード自身が離す位置まで先に動いて見える。ドロップ先は**親の枠だけ**を提示し、何番目の子になるかは提示しない（絶対配置の子はフローの並びから外れるので、並びの位置に意味が無い）
  - **離した位置の親が今の親と違えば、その親へ付け替える**。座標は**新しい親から見た値へ直して**書くので、画面上の位置は変わらない。付け替え先では並びの末尾（＝最前面）に入る。親の内側へ収める処理は持たない — はみ出した配置（カードの角から覗くバッジ等）はドラッグで作れる
  - **落とせる親が無い場所（artboard の外）で離しても何も起きない。** 座標は親から見た値なので、親が決まらなければ書く値も決まらないため。したがってドラッグで作れるはみ出しは、**掴んだ点が親の内側に留まる範囲**に限られる
  - ただし**運んでいる間の見た目は、落とせる親が無い場所でもポインタへ追従する**。落とせないことは**親の枠が出ないこと**で示す（追従を止めると、落とせない場所を一瞬通っただけでノードが元の位置へ戻り、運べているのか分からなくなる）
  - 親の付け替えを伴わない座標の指定（プロパティパネルで x / y を直接打つ経路）には、この制限は掛からない
- **artboard の移動**: artboard の**見出し**（名前と大きさが並ぶ行。枠の幅いっぱい）と、**枠の背景**（子ノードが乗っていないところ）を掴んでドラッグすると、キャンバス上の位置が動く（`x` / `y`。01-file-format「artboards」）
  - 掴み口を 2 つ持つのは、**箱だけ**を掴み口にすると子が全面を覆う artboard を掴めなくなり、**見出しだけ**にすると artboard 本体を掴んでも何も起きないため
  - **どちらの掴み口から運んでも選択は変わらない**（動かさずに押して離せば、背景はこれまでどおり選択になる）。中身を掴んだときはノードの移動（上記）になる
  - ノードの移動と違い**親の付け替えが無い**。artboard は誰の子でもないので落とし先の親が無く、原点より左・上へも置ける
  - 座標を持たない artboard（1.1 以前のファイル）は、掴んだ時点で**描かれている位置**が起点になる
- **リサイズハンドル**: `widthMode` / `heightMode` が `fixed` のノードにのみ表示し、ドラッグで `width` / `height` を変更する。`hug` / `fill` ではハンドルを出さない（スキーマのモードと直接操作が一致する）
  - ハンドルは**四隅と各辺の中間の 8 箇所**に出す（図形編集ツールの一般的な流儀。辺いっぱいの帯ではない）。UI 案 `docs/Design Composer.html` は Figma に倣って四隅の 4 個だけだが、そこからは意図的に離れている
  - ハンドルは**選択の枠の上に中心が来る**ように置く（辺をまたぐ）。要素の内側へ寄せると、枠のすぐ内側にあるノードと重なって見分けが付かなくなる
  - **掴める軸のハンドルの上では、カーソルがその軸のリサイズを表す形に変わる**。2 軸を同時に変えられる角では斜めのカーソルになる。掴めないハンドルではカーソルを変えない（できない操作を示唆しないため）
  - **右下の角は幅と高さを同時に変える**。原点（枠の左上）が動かないので、両方を増やすだけで済む
  - **リサイズすると、その中の絶対配置の子が `constraintX` / `constraintY` に従って動く**（03-schema「親のリサイズへの追従」）。プロパティパネルから `width` / `height` を変えたときも同じで、どちらの経路でも結果は変わらない
  - **掴めるのは右辺・下辺と右下の角だけ**。左辺・上辺・残る 3 隅から縮めるには反対側の辺を留める位置の補正が要るが、既定の `placement: "flow"` のノードは座標を持たないため補正できない（#371）。掴めない 5 個のハンドルは、選択の範囲を示す目印として描くだけ
  - **掴み口は描いてあるハンドルより広い**。右辺・下辺は辺の全長を掴める。**この帯は角でも 1 軸**で、2 本の帯が重なる角では幅が優先される（角の四角の外側・帯の内側を押すと、幅が固定なら幅だけが変わる）。角とみなす範囲を決めるのは掴み口全体の設計になるため、そこは #371 に残している
- **矢印キーによる移動**: 選択中のノードが `absolute` なら、矢印キーでその親の中の座標が動く（1px。Shift を押しながらなら 10px）。**親は付け替わらない** — 付け替えは落とし先の親が決まるドラッグだけの振る舞いで、キーからは落とし先が決まらないため。`flow` のノードと artboard を選んでいるときは何も起きない（動かす座標を持たない）
- **Text のインライン編集**: ダブルクリックで `content` をその場で編集する

## 編集操作の一覧

| 操作 | 内容 |
|---|---|
| 挿入 | プリミティブ（Box / Text）または部品インスタンス（ref）を選択位置に追加 |
| 削除 | 選択ノード（サブツリーごと）を削除 |
| 並べ替え | 同一親内の子順序の変更（ドラッグ・ツリービュー・キーボード）。キーボードは選択中のノードを 1 つ前面（⌘] / Ctrl+]）／背面（⌘[ / Ctrl+[）へ動かす。隣がいない向きへは動かない |
| props 編集 | プロパティパネル経由。トークン参照 prop はトークン一覧からの選択式 |
| artboard 操作 | 追加・削除・配列順の並べ替え・キャンバス上の移動（見出しまたは枠の背景のドラッグ。上記「キャンバス直接操作」）。並べ替えが動かすのは自動配置される artboard だけで、座標を持つ artboard の位置は配列順に依らない |
| tokens 編集 | 種別ごとの一覧・追加・変更・削除の UI を持つ |
| コピー & ペースト | サブツリー単位。**自動リネームで名前の一意性を保つ**（01-file-format） |
| undo / redo | メモリ内管理。適用は通常の編集として自動保存される（05-architecture） |
| 選択解除 | Esc。外れるのはノードの選択だけで、トークンの選択は残る |

キーボードだけで行う操作（削除・コピー & ペースト・undo / redo・選択解除・並べ替え・座標の移動）は、**フォーカスのある要素がそのキーを自分で受け取る間は効かない**。文字を打ち込んでいる最中はどの割り当ても通さず、選択欄（トークンを選ぶ欄など）では修飾キーを伴わない割り当てだけを通さない。

## 部品化・解除

### 部品化（Create Component）

- 選択サブツリーを `components` へ移動し、元の位置に参照ノード `{ name, ref }` を置く
- 操作時に部品名のみを入力させる。**publicProps 宣言（binding）はゼロで作成する**。宣言の追加は AI / JSON 編集で行う（宣言編集 UI は初期スコープ外）

### 解除（Detach）

- インスタンス（ref ノード）を、部品定義に overrides を適用した実ツリーへ展開して置き換える
- **overrides の焼き込み**: 展開結果は「定義 + そのインスタンスの overrides」を合成した状態とする（レンダリング用の合成処理を流用）
- **自動リネーム**: 展開される内部ノードの name は単一名前空間で衝突するため、コピー & ペーストと同じ自動リネーム規則を適用する
