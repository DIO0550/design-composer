穴テストで守れていない振る舞い

  • テンプレートの固定スクリプト全体(ナビの「なし」、地図の描画、古さの帯、行リンク、「解説に出てこない」の照合)。素の HTML のスクリプトを走らせる仕組みがリポジトリに無く、そのために依存を足す規模ではないと判断した。代わりにローカルのフィクスチャを Playwright で開き、1 ページ版で 5 状態(未記入・最新・古い・古い(追えない)・地図なし)、4 ページ版でナビとページごとの自動生成の節を目視した。変えたときに機械が気づけるのは CSP のハッシュの直し忘れだけ
  • Actions 上の認証経路。判定表はローカルの bare リポジトリで、認証を通らない。この PR の PR Explain の run が緑になったことで確かめた
  • gh-pages への問い合わせが失敗する経路(ls-remote が 0 と 2 以外を返す)。失敗を再現する環境を組めず、test-reviewer も計測していない
  • 引数の誤りで終了コード 2 になる経路の一部(地図の生成スクリプトの引数検査など)。呼び出し元が 2 つだけで、どちらも値を自分で決めているので見送った

実測壊して確かめた結果

1 ページの版では、test-reviewer が判定表の複製で合計 63 個の書き換えを入れ、落ちなかったもの(生き残り)を 11 種類報告した。うち 10 種類はケースを足して落ちるようにし、主なものは自分でも壊して落ちることを確かめた(テスト名の抜き出しの後読みを外す・新しく足したテストファイルを base から読む・「変更なし」の枝を消す・検査に落ちたときの即時終了を外す)。残した 1 種類は、引数の誤りの経路(上の「守れていない」の最後)。

4 ページに分けた版では、ページ名の所属・ページどうしのリンク・置き先のファイル名・終了コードの受け渡しを 22 通り壊し、落ちなかったのは data-page の突き合わせの片側(入口以外のページ・属性の欠落)と、--page が必須であることの 2 点だった。どちらもケースを足し、壊して落ちることを確かめた。
