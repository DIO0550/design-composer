技術技術解説

ブラウザCSP のハッシュでスクリプトを 1 本だけ許す

Content Security Policy(CSP)は、ページが「どこから何を読み込み、どのスクリプトを実行してよいか」をブラウザに宣言する仕組み。<meta http-equiv="Content-Security-Policy"> に書いておくと、ブラウザはそれに反するものを実行せずに捨てる。

この PR では script-src 'sha256-…' を使う。「中身の SHA-256 がこの値になるインラインスクリプトだけを実行してよい」という意味で、テンプレートの固定スクリプト 1 本だけが該当する。断片に <script> が紛れ込んでも中身が違うのでハッシュが合わず、onclick= のようなイベント属性や javascript: の URL も、'unsafe-inline' を許していないので動かない。4 ページとも同じ枠なので、ハッシュも 1 つで済む。

<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'sha256-…'; style-src 'unsafe-inline'; connect-src 'self'; …">
固定スクリプトを 1 文字でも変えるとハッシュが変わり、スクリプトが丸ごと止まる。build-pr-explain-page.py が毎回テンプレートのハッシュと中身を突き合わせ、合わなければ公開しない。

Pythonhtml.parser で「属性として」見る

危ない綴りを正規表現で探すと、解説の本文に出てくる onClick={handleClick} のような普通の文章まで引っかかる。そこで標準ライブラリの html.parser に断片を読ませ、タグとして開かれた要素と属性として付いた値だけを調べる。エスケープされた &lt;script&gt; はテキストなので、要素として報告されない。

属性の値は実体参照をデコードした後で渡されるので、&#106;avascript: も javascript: として見える。URL は許す接頭辞(このリポジトリの github.com・Pages・#)か、解説の 4 ページのファイル名だけを通す。接頭辞は末尾の / まで含めて design-composer-evil のような詐称を通さない。

コメント(<!-- -->)と CDATA は断片に書かせない。<!--> のような綴りを html.parser とブラウザが別々に解釈し、その中に置いた要素が検査を素通りしうるため(security-reviewer)。

gitpartial clone と sparse-checkout で 1 フォルダだけ取る

gh-pages は Storybook 本体・PR プレビュー・VRT の画像で約 352 MB ある。解説を 1 枚置くたびに全部を取るのは重いので、--filter=blob:none(ファイルの中身を後回しにする partial clone)と --depth 1 で clone し、sparse-checkout で pr-explain/pr-N/ だけを作業ツリーに展開する。実測で 1 秒ほど。

この展開の範囲は安全装置も兼ねる。remove 1 で消せるのは作業ツリーにある pr-explain/pr-1/ だけで、隣の pr-12 は展開されていないので触れない。

git clone --filter=blob:none --no-checkout --depth 1 --branch gh-pages "$remote" "$work/site"
git -C "$work/site" sparse-checkout set --no-cone "/$folder/"
git -C "$work/site" checkout gh-pages

gitmerge-base と、テスト名を集合で比べること

PR の「Files changed」は base の先端との差ではなく、PR が分岐した点(merge-base)からの差を見せている。地図も同じ範囲にするため、Actions から受け取った base の先端からまず merge-base を求める。地図の JSON のキーが mergeBase なのは、先端と取り違えないため。

テスト名の増減は、差分の行からは拾わない。ファイルを rename しただけ、名前を変えずに中身だけ直しただけ、test.each(…)( の改行の位置が変わっただけ、のどれでも同じテストが「削除 + 追加」に化けるため。前後のファイルの中身からテスト名を抜き出して集合の差を取る。抜き出しは test( / it( の直前が識別子の文字や . でないことを求める(テスト本体の "a,b".split(",") を it( と読まないため)。

Actions認証ヘッダを環境変数の git 設定で 1 本だけ渡す

pr-explain-pages.sh は作業用の別フォルダへ clone するので、actions/checkout がリポジトリの設定に置いた認証は引き継がれない。GIT_CONFIG_COUNT / GIT_CONFIG_KEY_0 / GIT_CONFIG_VALUE_0 という環境変数で、どのフォルダで走る git にも同じ http.extraheader を効かせる。checkout 側の認証が残っているとヘッダが 2 本になるので persist-credentials: false を付け、base64 にした値は ::add-mask:: でログから伏せる。

.github/scripts/build-pr-change-map.py

Actions が呼ぶ。build_map が入口で、merge-base を求め、changed_files(rename を 1 件に畳む)→ group_files(layer_of で層に分けて読む順に並べる)→ test_changes(前後の中身からテスト名を抜いて集合で比べる)→ commits_between(コミットごとの変更ファイル)の順に地図を組む。

.github/scripts/build-pr-explain-page.py

セッションが書いた断片を検査してテンプレートへ差し込む。FragmentScanner が要素・属性・コメントを集め、meta_problems が explain-meta(sha 40 桁・PR 番号・ページ名)を見て、assemble がマーカーの間を置き換える。違反があればページを書き出さない。

def assemble(fragment: str, template: str) -> str:
    before, rest = template.split(BeginMarker)
    _, after = rest.split(EndMarker)
    return f"{before}{BeginMarker}\n{fragment.strip()}\n{EndMarker}{after}"

.github/scripts/pr-explain-pages.sh

gh-pages の pr-explain/pr-N/ だけを書き換える。put-page(セッション)は組み立てたページを 1 ファイル置き、put-map(Actions)は地図を置いて入口が無ければテンプレートを置き、remove はフォルダごと消す。どれも checkout_site → apply_change → commit_and_push の順で、push が競合したら最大 5 回取り直す。
